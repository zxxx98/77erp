# 多配方、多层 BOM 与备料测算

桌面、移动 Web 和 PWA 从「生产 → BOM」进入，需要独立的「BOM」权限。物料详情提供「查看BOM」，按该成品筛选。管理员默认可用，员工由管理员授权。

## 配置与使用

1. 新建BOM，选择当前仓库已启用的成品，填写 BOM 名称、基准产量和备注。基准产量默认 1，也可按 10、100 等整批产量录入。
2. 搜索材料名称、编码或规格，或扫描已有物料条码 / 二维码添加材料；为整张 BOM 选择「标准损耗计算方式」（内扣法或外包法），填写各材料净用量、标准损耗率和备注。用量可填小数（如 `0.025`）或分数（如 `1/40`），单位使用物料档案中的单位。编辑、复制时保留原分数。
3. 保存后点击「测算备料」，输入生产数量，查看材料需求、读取时的账面库存和缺料数量，可导出同一份库存快照的 CSV 备料表。

成品和材料均引用现有物料档案，不新增物料类型。同一成品或半成品在当前仓库可有多份不同名称的配方，各自启停；每份最多 100 种材料，支持编辑、启停、复制和删除。列表中的「删除」须确认且无法恢复，删除同时清理材料与废料规则，不改变物料或库存。被上级 BOM 引用时须先解除关联；被生产单（包括已作废单据及历史多层快照）引用的配方不能删除，可改为停用；如关联的已作废生产单已被删除，则解除相应引用。复制会打开未保存的新清单，保留原成品、材料组合、损耗率、计算方式及下级配方关联，修改名称后即可为同一物料保存新配方，也可另选成品。

同一材料通过页面再次添加时合并用量；服务端拒绝重复行。成品不能作为自身材料。材料可通过「下级配方关联（可选）」明确绑定当前仓库的配方；没有关联时不自动选择某个 BOM。关联作为建单默认值，现做、领库或部分领库在创建生产单时决定。

保存或测算不改变库存、库存价值、采购销售单据及品质验收记录。实际耗料和成品入库通过独立的[生产单](production.md)记录，需要「生产单」权限；可从清单列表新建，或把测算数量带入生产草稿。BOM 测算本身不预留库存、不扣料、不创建任务。

## 多层测算与生产

同物料的多份配方通过 BOM ID 区分；编辑版本只是该配方的修订号。测算和生产明确选择根配方，各展开行明确绑定下级 BOM ID；新增或停用其他配方不会自动换配方。循环按 BOM ID 校验，限制最多 10 层、2000 个材料节点、500 种最终领料。

测算默认打开「领料汇总」，「配方结构」页签查看各层来源，切换保留浏览状态。汇总行不伪造统一单耗或损耗率，点击「查看 N 条来源」可定位该物料的全部路径；同一物料在不同分支的来源分别保留，库存与缺料仍只在汇总中计算。两个导出按钮分别导出同一次结果的备料表和完整结构明细，不受当前搜索、折叠或进入分支影响。

配方结构默认只显示根配方的直接材料。桌面支持逐行展开、展开到当前分支的第 2／3 层、全部收起；点击物料名称查看独立详情区的来源配方、修订、基准产量、净用量和损耗参数。可「进入分支」查看某个半成品的直接材料，用顶部路径或「返回上一级」返回并恢复浏览位置。手机、平板和 PWA 以逐层进入为主，节点详情在底部面板中查看。物料名称／编码搜索覆盖整个配方，桌面保留匹配项的祖先结构，手机逐条显示匹配路径；清除搜索恢复当前分支。进入分支只改变查看范围，本次需求仍按根成品的生产数量计算。生产单的配方快照复用同一浏览方式。

备料按毛需求展开，中间半成品账面库存不抵扣下层需求，也不生成中间件入出库；只有最终领料项汇总后抵扣一次库存以计算缺料。新建多层生产单可在同一单内逐层登记半成品产量、直属耗料和进度，再供对应上层使用，详见[子 BOM 分层登记](production.md#子-bom-分层登记)。不会自动生成半成品生产单或采购单。需要先生产入库的半成品可用独立生产单生产，再在上层生产单中选择「使用库存」。

被展开的下级配方本期不能带废料规则。根配方按产量废料继续可用；根配方按投入比例废料的来源必须是直接领用且不在其他展开路径重复出现的材料。违反时明确报错，不忽略废料规则。

新客户端测算及生产写入声明 `schema_version: 2`。测算返回完整 `nodes`、最终领料 `rows` 及 `structure_token`；多层建单须携带该凭证，根或已选子配方变化后返回 409 并要求重新预览。旧页面遇到多层操作提示刷新。原单层行为继续兼容。

## 数量和单位

计算方式在每张 BOM 的「材料用量」区域选择，适用于全部材料：

- 内扣法（`loss_method=internal`）：`本次材料需求 = 材料基准净用量 × 生产数量 ÷ 基准产量 ÷（1 − 标准损耗率 / 100）`，损耗率按投入量计算。
- 外包法（`loss_method=external`）：`本次材料需求 = 材料基准净用量 × 生产数量 ÷ 基准产量 ×（1 ＋ 标准损耗率 / 100）`，损耗率按净用量计算。

标准损耗率配置在每条 BOM 材料明细，单位为百分数，`10` 表示 10%，可填 0（含）至 100（不含），最多 6 位小数。同一材料在不同 BOM 可以使用不同损耗率；默认 0%，原有用量和历史单据保持原结果。已有 BOM 默认内扣法，计算结果保持原样。净用量 90、损耗率 10%，内扣法标准投入为 100，外包法为 99；净用量 100、损耗率 5%，内扣法为 105.2632，外包法为 105。生产单保存建单时的计算方式，后续更改 BOM 不影响已有生产单。已有用量若已包含损耗，应先核对净用量，避免再加一次。损耗率仅用于标准与计划，不直接扣库或生成废料。

小数用量沿用现有正数、最多 4 位小数及 99999999 上限。分数的分子、分母均为 1–99999999 的整数，不支持零分母、负数、带分数或其他算式。使用 BigInt 保留原分数和损耗率合并进行乘除，需求仅在最终计算时向上进位至 4 位小数；例如 `1/3 × 3 = 1`，不会提前把 `1/3` 转为小数再计算。缺料为 `max(需求 − 账面库存, 0)`。

例如每个纸箱装 40 条电线，可以填写基准产量 1 条、纸箱用量 `1/40` 个，生产 40 条需 1 个纸箱、80 条需 2 个。也可继续填写基准产量 40 条、纸箱用量 1 个。分数表示标准分摊量，不按“个”“箱”等单位名称推断整件取整；未启用取整时，生产 41 条的标准用量为 1.025 个；在纸箱物料勾选「单位是否取整」后，计划用料和标准耗料会自动向上取整为 2 个。同一物料多条路径先合并最终领料再取整；取整的中间半成品按整数产量展开下级配方。

BOM 保存配置时的成品及材料单位。档案单位变化后，已有配方仍可查看；测算会要求先编辑、核对基准产量或用量并重新保存。停用清单、成品或任一材料时不能测算。已引用物料不能直接删除，可保留档案并停用。删除零库存仓库和重置业务数据时同步清理其 BOM。

## 并发、权限及备份

保存、启停和删除检查清单版本，冲突返回 409 并保留页面填写内容。写入使用现有按用户隔离的请求标识避免重复提交。版本序列持久保存，重置或恢复后旧编辑页面不能覆盖新数据。离开未保存页面时沿用全站离开确认。

所有 BOM API 需要登录及 `bom` 权限，资源按当前仓库隔离，不返回财务成本。该权限同时覆盖维护、测算和导出，不授予物料编辑、库存调整或采购销售权限。数据变动接入现有更新提示。

业务备份格式 33 新增物料及生产快照的 `unit_round_up`、生产单的 `quantity_decimals`；旧数据默认不取整，旧生产单保留 6 位精度，新单使用 4 位，恢复不截断历史数据。格式 31 增加 BOM 和生产单的 `loss_method`，格式 1–30 恢复为内扣法。格式 25 在格式 23 的 `boms`、`bom_items` 基础上增加材料原分数。恢复校验成品、材料、仓库、单位字段、数量与分数一致性及唯一关系；格式 1–24 的用量按原小数恢复，格式 1–22 恢复为空清单。BOM 变更会使旧恢复预览失效，恢复时重新分配编辑版本。R2 数据库备份自然包含分数。

## 结构节点标注

配方结构列表在物料名下显示物料档案当前生产类型（未填写时显示「类型未设置」）及节点相对根配方的层级。根配方产物为第 0 级，直接材料为第 1 级；进入子分支或搜索时层级不重新编号，同物料在不同路径可处于不同层级。节点详情同步显示这两个字段，桌面、移动 Web 和 PWA 保持一致。生产单结构及用量仍为保存时快照，当前生产类型只用于展示，不改变供料方式或参与需求计算。

测算、生产单预览与详情的 `nodes[].current_production_type` 在读取时按当前仓库批量查询物料档案，空字符串表示未设置；不持久化到配方快照，不影响 `structure_token`。层级为 `path` 按点分段数。

## AI 助手

同时需要「AI 助手」和「BOM」权限。`search_boms` 查找当前仓库清单，`get_bom` 读取实际配方，`calculate_bom` 使用明确的生产数量进行同一规则的备料测算。查询不生成写入卡片，也不执行领料。AI 不创建、修改或删除 BOM，删除须到 BOM 列表确认。关闭 AI 写操作后仍可使用这些查询。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/boms?q=&status=&product_id=&offset=&limit=` | 分页查找当前仓库清单，状态为 all / enabled / disabled |
| GET | `/api/boms/:id` | 查看清单、成品和材料档案 |
| POST | `/api/boms` | 新建，包含 request_id |
| POST | `/api/boms/:id` | 编辑，包含 request_id 和 version |
| POST | `/api/boms/:id/status` | 启停，包含 request_id、version 和 enabled（0 / 1） |
| POST | `/api/boms/:id/delete` | 删除未被引用的清单及材料、废料规则，包含 request_id 和 version |
| POST | `/api/boms/:id/calculate` | 只读测算，包含 production_quantity，可附 version 校验当前清单 |

配置包含 `name`、`product_id`、`base_quantity`、`base_unit`、`loss_method`、`note`、`enabled`，以及 `items: [{product_id, quantity, quantity_fraction, loss_rate, unit, note}]`。`quantity_fraction` 可省略或为空，表示普通小数；非空时为规范的正整数分数（如 `1/40`），`quantity` 必须等于该分数向上保留 4 位小数的数值，供既有客户端读取。共享函数 `parseBomQuantity` 可生成这两个字段。`loss_method` 为整张 BOM 的损耗计算方式，只允许 `internal`（内扣法）或 `external`（外包法）；新建省略默认为内扣法，旧客户端编辑时省略则保留原方式。`loss_rate` 为标准损耗百分数；新增时省略为 0，编辑旧客户端省略时保留同材料已有损耗率，显式传 0 才清零。服务端校验一致性，按原分数和损耗率测算，并验证物料属于当前仓库且已启用、单位未变化。测算明细同样返回原分数，不保存测算记录。

CSV 使用带 BOM 的 UTF-8，记录名称、成品、仓库、基准产量、生产数量、库存读取时间、损耗计算方式及材料明细；文本字段防止公式执行，数值按快照导出。分数基准用量导出为 `1/40（约 0.025）`，保留比例并避免电子表格将其识别为日期。修改生产数量会清空上次结果，需要重新测算。

## 废料产出

「废料产出」是可选配置，直接选择当前仓库的现有物料，不新增废料档案或物料类型。同一废料可以被不同 BOM 引用，各 BOM 独立配置计算规则。每张 BOM 最多 100 种废料，废料不能重复、不能与成品或投入材料相同；可继续作为原料使用的剩余数量属于余料，实际耗料填净消耗量。

- `output` 按产量计算：`预计废料 = 基准废料量 × 生产数量 ÷ BOM 基准产量`。支持小数和原分数，沿用材料数量的最终向上保留 4 位小数规则。
- `input_ratio` 按指定材料投入计算：`预计废料 = 来源材料投入 × quantity ÷ 100`。`quantity=3` 表示 3%，最多 4 位小数，必须大于 0 且不超过 100；同一来源材料的比例合计不能超过 100%。来源必须是本 BOM 的投入材料，废料与来源单位必须一致，不自动做 kg/g、件/kg 等换算。测算时先计算包含标准损耗的计划投入，再据此计算废料；完工时使用实际耗料，不再乘损耗系数。废料不得再次加到标准投入或从实际耗料中扣除。

规则字段为 `scraps: [{product_id, method, source_product_id, quantity, quantity_fraction, unit, note}]`。按产量的 `source_product_id` 固定为 `null`；比例方式必须指定材料 ID，不接受分数百分比。保存时省略 `scraps` 会保留已有规则，显式传 `[]` 才清空，兼容旧客户端编辑。

测算返回 `scraps`，含物料资料、规则和 `planned_quantity`。页面和 CSV 同时展示预计废料及比例来源；测算仍不改变库存。复制 BOM 会保留废料规则。废料物料停用或单位改变时，需要先核对才能继续测算或建单。仅被废料规则引用的物料也不能删除。

业务备份格式 26 增加 `bom_scraps`，校验来源、单位、比例、排序和仓库关联。格式 1–25 恢复为空废料规则，原有 BOM 数据按对应版本规则恢复。

业务备份格式 28 增加 `bom_items.loss_rate` 和生产材料的损耗率快照，保留并校验比例。格式 1–27 恢复时自动补为 0，不根据废料比例推测历史损耗率。CSV 同时导出基准净用量、标准损耗百分数及含损耗需求。

业务备份格式 32 支持同物料多份 BOM，增加材料行 `usage_mode`、`child_bom_id` 及多层生产节点快照。格式 1–31 的原行恢复为直接领用，保留原 BOM ID，不补造历史展开关系。完整设计见 [第一期设计文档](bom-multilevel-phase1-design.md)。


### 配方与生产安排

BOM 编辑不再设置本次“用料方式”，仅维护配比及可选下级配方关联。新建生产单时逐项选择本单生产、使用库存或部分使用库存，并明确本次采用的下级配方。历史关联保留为建单默认值。BOM 的独立备料测算仍按其原关联展开毛需求；生产单按本次选择重新测算和保存快照。详见[创建生产单时选择半成品来源](production.md#创建生产单时选择半成品来源)。
