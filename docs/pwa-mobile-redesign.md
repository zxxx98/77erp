# 77 ERP 移动网页版 / PWA 重构方案

日期：2026-10-14。已交付设计方案、交互原型、静态设计图及首期移动网页版 / PWA 实现；原型数据为示例，代码尚未部署到公网。

当前实现：按设备识别选择移动与 PC 界面，手机和平板均使用移动端；安卓对应的五项导航、工作台、商品/库存列表、商品及单据详情、全屏入出库和二次确认；PWA 安装与更新、应用界面预缓存、离线状态、本地草稿以及原请求重试保护。设置、商品编辑、财务、盘点等复用已有业务组件。仍使用 `/api/data` 全量数据，列表每次增加 30 条显示属于客户端渲染限制，服务端分页、离线库存查询、自动同步及推送尚未实现。安装、真实摄像头和系统键盘仍需 HTTPS 真机验收。

## 推荐方向

使用现有 React 19 + Vite 7 前端与 Express + SQLite 后端，增加专门的移动端界面。共享账号、仓库、权限、金额与数量规则、二维码协议及业务 API。独立 React Native 安卓端继续使用既有 API；无需为 PWA 改写成 React Native Web。

以当前 React Native 安卓端 UI 为统一基准：对应页面保持导航、指标顺序、按钮文案、筛选语义和开单确认流程一致。视觉实现依据 `mobile/src/App.tsx`、`mobile/src/screens.tsx`、`mobile/src/forms.tsx`、`mobile/src/ui.tsx`；HTML 原型是按源码还原的设计预览，不是原生实机截图。

PWA 在安卓界面结构上增加安装、网页版本更新、本地草稿和离线状态。页面与业务代码使用 React DOM 实现，共享样式令牌及业务规则，不直接把 React Native 组件复制到 Web。

## 现状与重构依据

| 项目现状 | 对方案的影响 |
| --- | --- |
| `src/styles.css` 在宽度 ≤760px 时保留 72px 图标侧栏，`src/main.jsx` 共用桌面页面及弹窗 | 手机应使用完整宽度、底部导航、独立列表和全屏表单 |
| `mobile/src/App.tsx` 已采用工作台、商品、库存、单据、更多五个标签 | 延续这套业务组织，降低安卓与网页之间的学习成本 |
| `src/api.js` 使用同源 Cookie 与 `X-Warehouse-ID` | 保持同源部署，草稿和页面状态始终绑定仓库 |
| `server/auth.js` 对 `/api` 返回 `Cache-Control: no-store`，权限在服务端校验 | Service Worker 不缓存 API；PWA 安装不改变登录有效期或授权方式 |
| `server/operations.js` 已有按用户隔离的 `request_id` 及请求内容指纹 | 重试必须保持用户、仓库、请求内容和标识一致，不能盲目生成新标识 |
| 商品编辑已有 `version`，盘点有库存变化校验 | 保留冲突机制；离线草稿不是自动覆盖最新数据的依据 |
| `/api/data` 仍包含当前仓库完整商品与历史单据 | 可以用于第一阶段兼容迁移；数据量增长后需要分页查询及工作台聚合接口 |
| README 中现有公网演示地址为 HTTP | 正式 PWA 和手机相机扫码须先部署 HTTPS；手机访问局域网 HTTP IP 通常也不满足安全上下文条件 |

## 信息架构

底部五项：**工作台 / 商品 / 库存 / 单据 / 更多**。扫码是动作入口，不占第六个标签；工作台与商品/开单页面均提供扫码按钮。

| 页面 | 主要内容 | 主要操作 |
| --- | --- | --- |
| 工作台 | 当前仓库、商品种类、库存成本、今日采购/销售、库存预警、最近单据；成本沿用权限遮蔽 | 扫描商品条码、采购入库、销售出库、查看全部单据 |
| 商品 | 搜索、树形分类筛选、上架状态、商品卡片、图片及规格 | 查看详情；有权限时新增/编辑、上下架、标签、跨仓同步 |
| 库存 | 全部库存/库存预警/缺货；沿用安卓商品行 | 从商品详情补货、报损；盘点与跨仓数量对照从业务管理进入 |
| 单据 | 采购/销售/退货/作废状态，日期和往来单位筛选，详情 | 开单、套用模板；按权限收付款、退货、作废、导出 |
| 更多 | 工作空间：账号、商户/仓库、修改密码、业务管理、当前站点、退出；增加网页版应用分组 | 业务管理内按权限显示往来/模板/二维码/财务/盘点等；网页版应用含安装、更新、本地草稿 |

所有主要页面标题明确当前仓库；仓库切换面板可以搜索，切换时清空旧查询结果并拒绝过期响应。开单时仓库为只读，离开编辑页先保存或放弃草稿再切换。

移动端保留已有功能的可达入口。批量导入、多仓库盘点和备份等复杂页面可先提供响应式兼容页，并提示文件/规模限制，随后逐个重构。现有页面 hash、查询参数及安卓跳转链接需要保留兼容映射。

## 页面与交互

### 工作台

顺序与安卓一致：商户/仓库副标题 → 商品种类、库存成本、今日采购、今日销售 → 快速操作 → 库存预警 → 最近单据。库存成本在无权限时显示「—」，采购/销售按钮按权限显示。点击顶栏扫码或「扫描商品条码」后才开启扫码流程。

保持卡片排列与入口位置对应，不新增首页方案选择。桌面的 7/30 天趋势可以继续保留在桌面端；后续如要新增到移动首页，应同步评估安卓端信息架构。

### 商品与库存

沿用安卓 `ProductRow` 的分层结构：左侧 46px 商品缩略图；右侧名称、编码、规格，再显示分类与库存状态，最后是库存和售价。商品与库存页共用商品行。筛选默认以安卓同名选项展示，分类保持层级；超长分类允许展开选择面板，不改变筛选语义。库存预警包含零库存，与安卓当前 `stock <= threshold` 规则一致。首期使用现有全量 API 和客户端搜索，后续长列表改为服务端搜索与分页。

商品详情提供查看图片、标签、其他仓库存量及入出库入口。库存页的补货进入采购草稿，不立即调整库存。报损必须填写原因，展示变更前后数量并进行在线确认。金额与数量继续使用 `shared/money.js`、`shared/quantity.js`，不能将六位小数数量转换成整数步进器。

### 开单

路径：选择采购或销售 → 选择往来单位 → 搜索/扫码/模板加商品 → 编辑数量与成交单价 → 核对仓库、总金额及明细 → 在线提交 → 成功详情。

全屏编辑替代桌面居中弹窗，沿用安卓顶部返回/关闭与底部「确认入库/确认出库」。点击后显示确认面板，提供「继续编辑 / 确认提交」，不新增单独的核对页面。数量与单价直接输入，保留加减按钮与单行金额；模板及备注入口与安卓对应。字段输入字号 ≥16px，商品最多 100 行沿用现有后端限制。添加同一商品合并数量，精度不丢失。示意稿只展示模板选择入口，保存/更新模板的条件分组在实现时按现有权限与安卓表单补齐。

最终确认明确显示「销售出库」或「采购入库」、仓库、往来单位和总金额。提交期间禁用重复操作；返回成功响应才显示成功，不使用乐观库存扣减。库存不足、权限改变、会话失效、商品不存在等失败保留草稿并提供下一步。

### 扫码

默认扫码查询；采购/销售模式通过显式入口进入。复用 `@zxing/browser` 和 `src/product-scan.js`，后置摄像头优先。识别后停止或暂停扫描，避免同一画面重复加单；明确操作后继续。

区分商品码与业务二维码，校验服务器来源、仓库、版本。商品码只定位商品；业务二维码沿用现有确认开关和执行规则（包括已配置的免确认模式），不因前端重构改变既有业务语义。离线时禁用业务二维码执行；跨仓码提示切换仓库，不能偷偷切换并提交。

摄像头权限拒绝或能力不支持时保留手动条码/名称搜索入口。不展示模拟扫码成功或固定示例条码。后台、离页和关屏释放摄像头。相册识别可作为后续选项；应测试实际设备格式与识别率后开放。

### 状态与视觉规范

- 延续现有 `#2563EB` 蓝色、`#F7F8FA` 背景、浅色卡片与克制状态颜色，深色模式另设对应可读令牌。
- 对应安卓现有令牌：正文 15px，字段输入 16px，辅助文字 13px，页面标题 27px，卡片标题 18px，指标 23px，详情值 18px；金额与数量使用等宽数字。
- 对应安卓普通卡片圆角 14px、指标卡 12px、按钮/输入框 9px，页面水平留白 20px，卡片内边距 18px；按钮与图标触摸区域至少 48×48px。网页文字缩放与窄屏时允许换行，不能为照搬数值而造成遮挡。
- 生产界面顶部与底部适配 `env(safe-area-inset-*)`，页面使用 `100dvh`，键盘弹出时调整底部按钮而不遮挡输入。
- 主导航使用浏览器历史，详情/编辑页支持系统返回；关闭有未保存变更的表单时提供保存草稿、放弃、继续编辑。
- 明确区分加载、空数据、搜索无结果、刷新失败、离线、权限不足和冲突。保留已加载数据时显示更新时间，不把旧库存标成实时。
- 输入错误关联字段，图标按钮有可读名称；遵守减少动效偏好。生产确认面板需要正确焦点管理。

## PWA 技术设计

### 安装、路由和更新

建议用 `vite-plugin-pwa` + Workbox 管理 Service Worker，使用提示更新模式（例如 `registerType: 'prompt'`），不强制刷新编辑中的页面。

Manifest 配置 `name: 77 ERP`、`short_name: 77 ERP`、稳定 `id`、`start_url: /`、`scope: /`、`display: standalone`、蓝色 `theme_color`、背景色，以及 192/512 普通与 maskable 图标。单独提供适合 iOS 的 apple-touch-icon。实际部署在子路径时这些路径随 Vite base 一并调整。

Chromium 浏览器在支持时展示安装入口；iOS Safari 提供「分享 → 添加到主屏幕」说明。未安装的浏览器仍有完整业务入口。首期同源服务，不照搬原生安卓端任意服务器地址配置。

应用壳可离线打开，首次使用需要联网。新版本下载后提示更新：无未保存变更可刷新；有草稿先保存再刷新。避免全局自动 `skipWaiting` 和自动 reload。资源部署保留上一版本带 hash 的静态文件，支持已打开页面的懒加载；HTML 更新策略与服务器资源版本一致。

### 缓存边界

| 内容 | 首期策略 |
| --- | --- |
| 版本化 JS/CSS、离线提示、安装图标 | 预缓存，版本升级清理旧应用资源 |
| 页面导航 | 已安装应用离线时返回缓存的应用壳；在线更新入口文档 |
| `/api/**`（含鉴权、库存、财务、图片上传） | NetworkOnly；不进入 Cache Storage，不修改现有 no-store 约定 |
| 商品图片 | 首期遵守原图服务器策略，不新增永久图片离线缓存 |
| 本地编辑草稿 | IndexedDB，独立于 Service Worker 的资源缓存 |

首期刷新后离线页面仅展示离线入口与可恢复草稿，不承诺完整商品/单据检索。当前页面断网后可以继续查看内存中的数据，但标注更新时间且禁用库存变更。`navigator.onLine` 仅作提示；在线判断结合实际 API 请求结果，不能将所有请求失败都归类为断网。

如果后续需要离线查询，另设计经授权的字段白名单快照与过期策略，不直接缓存 `/api/data`。离线时无法即时获知账号停用和权限撤回，应纳入设备使用约束再决定是否开放离线业务数据。

### 草稿、认证和不确定提交

草稿按 origin / 用户编号 / 仓库编号 / 草稿编号隔离，记录业务类型、商品编号、必要名称快照、数量、价格、版本和保存时间，不保存 Cookie 或密码。默认保留 7 天，可手动删除；退出登录清除本账号本地草稿。会话过期时隐藏草稿，重新登录同一账号且验证权限后才恢复；不同账号不能看到前一个账号内容。浏览器可能回收本地存储，显示保存失败和草稿保存时间，不能宣称永久保存。

恢复草稿后在线重新读取商品与仓库，检查存在性、权限、单位、价格、档案版本和库存。自动草稿不会改数据库。离线可以编辑已有草稿；搜索与新增商品选择需要联网。服务端校验仍为最终依据。

普通单据提交生成稳定 `request_id`，持久化提交时的原始请求快照。发生超时或响应丢失时显示「提交结果待确认」，锁定该请求内容；用户点击核对/重试时以同一账号、仓库、正文和 `request_id` 重发，依靠现有回执返回原结果。不能在未知结果下直接修改请求后重发，也不能生成新标识再次扣库。结果确定失败后才允许编辑并创建新的提交尝试。

首期不使用 Background Sync 或 Service Worker 自动重放库存、收付款和二维码操作。扫码业务码有单独执行协议，重试保护需要逐接口核实，不能把普通开单的机制视为覆盖全部写操作。

保持 HttpOnly、SameSite Cookie、服务端来源校验和权限校验。已安装 PWA 与浏览器的会话/存储共享行为以平台实测为准，不依赖原生 APK 的登录态。401 回登录、403 隐藏/禁用操作、409 保留输入并显示冲突处理；不把 Cookie 改成 localStorage token。

## 建议代码边界

```text
src/
  app/                 鉴权、路由、仓库上下文、权限、错误边界
  desktop/             迁出的现有桌面壳及页面
  mobile-web/
    shell/             顶栏、底部导航、全屏编辑容器
    pages/             工作台、商品、库存、单据、更多
    components/        商品行、筛选面板、数量输入、扫码
  features/            可复用的商品、开单、单据、盘点业务 hooks
  pwa/                 注册、安装入口、更新通知、草稿存储
shared/                继续共享金额、数量及权限规则
```

首期保留 `src/main.jsx` 的共用 API 状态、仓库和权限逻辑，增加 `src/mobile-web/MobileShell.jsx`、移动开单与详情、`src/pwa/` 注册与草稿存储；共用已有业务组件。更细的目录拆分为后续维护建议。

按用户确定的设备识别方式选择展示壳，禁止用宽度切换移动 / PC：`userAgentData.mobile === true`，或 UA 匹配手机/平板设备，或 `Macintosh` 且 `maxTouchPoints > 1` 的 iPadOS 使用移动界面；其余使用 PC 界面。无需手动切换入口。窗口大小只控制排版，手机横屏、平板大屏和 PC 窄窗口保持各自界面及输入状态。

## 落地顺序和验收

1. **设计与基础拆分**：以安卓现有界面建立对应组件表；移动顶栏/导航/路由/全屏容器；提取共用业务规则与 API hooks。交付可联机运行的移动工作台、商品与库存查询。
2. **交易闭环**：采购/销售、扫码、单据详情、盘点/报损及权限状态。验收搜索/扫码 → 添加商品 → 核对 → 提交 → 库存与单据刷新，库存不足整单回滚。
3. **PWA 能力**：HTTPS、Manifest/图标、应用壳缓存、安装/更新提示、按账号仓库隔离的草稿、不确定提交恢复。
4. **复杂业务与性能**：往来、模板、财务、业务二维码、复杂管理页面；按数据规模补分页 API，做真机回归后渐进发布。

以 1 名熟悉项目的前端开发者估算，核心移动交易闭环与 PWA 约 3–5 周；全部现有复杂功能重做约 5–8 周。仅是粗估，API 拆分、实际数据规模、浏览器兼容及回归范围会影响工期。

最低验收范围：

- Android Chrome 和安装后 PWA；iPhone Safari 和添加到主屏幕后；320/360/390/430px、横屏、键盘、安全区、系统返回。
- 同一账号、同一仓库和同一数据下，对照安卓真机检查顶栏、导航、指标排列、商品行、筛选语义、模板/开单入口、确认弹窗及权限隐藏；网页预览不能替代原生截图与真机验收。
- 真机后摄像头、拒绝权限、相机不可用、重复识别、商品码/业务码/跨仓码/跨服务器码，以及离页释放摄像头。
- 离线打开、断网前后草稿、刷新恢复、不同账号/仓库隔离、退出清理、会话过期、账号停用及权限撤回。
- 已提交但丢失响应的重试，仅生成一个单据；未知提交结果不得产生第二笔交易。
- 数量六位小数、价格两位小数、单行金额与后端一致、库存不足、商品版本冲突、盘点期间库存改变。
- 编辑时出现新版、保存草稿后更新、旧页面懒加载文件保留；Cache Storage 中没有 `/api` 响应。
- 初期、当前规模及约 1 万商品/数万单据的压力样本；分页阶段检查首屏不下载完整历史。Lighthouse 可辅助检查 Manifest、可访问性与性能，不能替代安装/离线/扫码真机验收。
