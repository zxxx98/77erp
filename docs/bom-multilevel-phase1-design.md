# 多层 BOM 第一期设计稿

状态：已按确认方案实现。基于应用 1.15.16，兼容各层内扣法／外包法。

## 1. 目标与范围

第一期交付「同一物料多份 BOM、BOM 明细可选展开方式、多层备料测算、生产配方快照」。桌面 Web、移动 Web 和 PWA 使用相同业务规则。

本期沿用现有物料档案，同一仓库中的同一种成品或半成品允许创建多份 BOM；在每条 BOM 材料明细上选择「领用本物料」或「展开下级 BOM」，展开时明确指定使用哪份下级配方。数据结构不写死两级，可以继续嵌套；生产单按展开后汇总的最终领料项登记耗料。

| 本期包含 | 后续阶段 |
| --- | --- |
| 同一成品／半成品多份 BOM、明确选择根及下级配方 | 默认配方、按日期／客户／批量自动选择配方 |
| 明细用料方式、下级 BOM 关联及校验 | 物料默认自制／采购／委外及供应策略 |
| 多层结构、各层需求、最终领料汇总及缺料 | 按半成品库存自动切换展开数量、库存预留 |
| 各层分数、基准产量及标准损耗精确计算 | 自动生成、关联及排程子生产单／采购单 |
| 生产单完整结构快照、按快照分批完工 | 工艺路线、标准／实际工时、计件／计时工资 |
| CSV、备份恢复、权限及 AI 只读查询同步 | 人工及制造费用进入生产成本 |

现有分批完工、材料成本结转、单批／整单作废继续适用。涉及废料的展开边界见第 7 节，这是本设计需要评审的主要范围取舍。

## 2. 明细行的业务规则

### 2.1 用料方式

| 选项 | 含义 | 实际领料 |
| --- | --- | --- |
| 领用本物料（默认） | 在这一行停止展开；该物料即使有自己的 BOM，也不自动使用 | 领用这一行物料 |
| 展开下级 BOM | 使用该物料在当前仓库的下级配方继续计算；这一行作为结构节点 | 领用下层最终领料项 |

「展开下级 BOM」的行内说明：**本单不领用、不入库此半成品，按下级配方备料。**

这不是物料类型设置。同一个 B，在 A 的 BOM 中可以直接领用，在 D 的 BOM 中可以展开。一个 BOM 内也可以混合两种方式。

- 原有 BOM 全部迁移为「领用本物料」，结果保持不变。
- 新增材料也默认「领用本物料」，不能因为发现它有 BOM 就自动改为展开。
- 同一 BOM 内同一物料仍只能有一行，不能同时配置两种方式；不同分支可以重复引用同一物料。
- 复制 BOM 时保留成品、明细用料方式和已选下级关联，填写新的配方名称即可为同一物料新增一份 BOM，也可另选成品；保存时重新校验，并生成独立的 BOM ID 和编辑版本。
- 本期生产单不能临时覆盖用料方式。需要采用其他方式时，先调整 BOM，再创建新生产单；已有生产单保留原快照。

### 2.2 同一物料的多份配方

同一成品或半成品可以有「标准配方」「替代材料配方」「客户专用配方」等多份 BOM，各自独立维护基准产量、材料、废料、启用状态及编辑版本，允许多份同时启用。

- 每份 BOM 使用独立、稳定的 BOM ID 标识。名称去除首尾空白后，在同一仓库、同一物料下不能重复；不同物料可以使用相同配方名称。
- 「多份 BOM」表示多套独立配方；每份配方的 `version` 仍是用于并发控制的编辑修订号，两者不能混用。
- 本期不增加默认配方或自动生效规则。按物料查看 BOM 时展示全部配方，不取第一份、最新一份或任意启用配方代替用户选择。
- 停用一份配方只影响该配方及明确引用它的展开链，不自动替换为同物料的其他配方。

### 2.3 下级 BOM 的选择

选「展开下级 BOM」时，增加必填的「下级配方」选择器，仅列出该行物料在当前仓库的 BOM，展示 BOM ID、名称、基准产量、状态和当前编辑版本。停用配方可显示原因，但不能用于新的展开选择。

无论候选是一份还是多份，均由用户确认具体配方，保存其 `child_bom_id`；已有选择回显原关联，不根据名称或候选排序重新匹配。没有可用配方时提示先建／启用下级 BOM，或改选「领用本物料」。

例如 B 有「B 标准配方」和「B 替代配方」，A 的 BOM 明细明确绑定前者，D 的 BOM 可以绑定后者；新增 B 的第三份配方不会改变 A、D 的展开结果。

BOM 档案使用所选下级配方的当前内容，所选子 BOM 修改后，下次新测算采用新内容；未选配方的修改不影响该展开链。生产单保存自己的各层配方身份及内容，不随档案变化。

## 3. 计算口径

### 3.1 逐层计算

每个 BOM 独立保留基准产量及内扣法／外包法，每条材料独立保留净用量、原分数和标准损耗率。内扣法：

```text
某行需求 = 当前层所需产量 × 该行基准净用量
           ÷ 当前层 BOM 基准产量 ÷（1 − 该行损耗率 / 100）
```

外包法将最后的 `÷（1 − 损耗率 / 100）` 改为 `×（1 + 损耗率 / 100）`，每层使用各自配方的算法。

若该行展开，其含损耗需求就是下级 BOM 的所需产量；下级再使用自己的基准产量及各行损耗率计算。每条边的损耗只计算一次，不在汇总后再加损耗。

计算期间使用 BigInt 有理数，不把中间需求先向上保留 6 位小数后再往下乘。结构节点展示值向上保留 6 位，但展示值不作为后续计算输入。

同一最终领料物料通过多条路径出现时，先汇总各路径的精确值，再统一向上保留 6 位小数。路径展示值的和可能略大于汇总值，页面和导出注明「汇总按未舍入值计算」。

数量上限、损耗率范围及录入精度沿用现有规则，不按单位名称自动整件取整，不自动换算 kg/g 等单位。

### 3.2 库存与缺料

本期采用**毛需求展开**：

- 「领用本物料」的行进入最终领料汇总，按物料汇总后仅抵扣一次当前仓库账面库存。
- 「展开下级 BOM」的中间件不抵扣库存，其账面库存可供参考，但不能减少下层需求。
- 中间节点不显示可执行的「缺料数量」，避免与实际领料混淆。
- 最终缺料为 `max(最终领料汇总需求 − 当前仓库账面库存, 0)`。
- 测算不预留库存、不扣库、不自动采购，也不自动安排半成品生产。

同一物料既在一个分支直接领用、又在另一个分支展开时，只有直接领用的部分计入该物料的领料需求；展开部分继续进入下层，不能相互抵扣。

### 3.3 示例

配置：选中的 A 配方每 1 个需要 B 2 个、C 1 个；展开 B 时指定的「B 标准配方」每 1 个需要 C 3 个，损耗均为 0。B 的其他配方不参与本次计算。

生产 A 10 个，B 库存 8 个，C 库存 20 个：

| B 的用料方式 | 中间需求 | 最终领料汇总 | 缺料 |
| --- | --- | --- | --- |
| 领用本物料 | 无 | B 20 个、C 10 个 | B 12 个、C 0 个 |
| 展开下级 BOM | B 20 个 | C 70 个 | C 50 个 |

第二种方式不会使用库存中的 8 个 B。若业务需要使用这 8 个 B，再对剩余 12 个 B 展开，本期不自动处理这一混合方案。

## 4. 页面交互

### 4.1 BOM 编辑

BOM 列表按物料筛选时显示该物料的全部配方，每行展示 BOM ID、名称、成品／半成品、状态和编辑版本；物料详情的「查看 BOM」进入配方列表。「新建」允许继续选择已有其他 BOM 的物料，「复制」允许为原物料新增配方。

材料明细增加「用料方式」及展开时必填的「下级配方」，保留净用量、原分数、单位、损耗率和备注。

选择展开后，行下方显示所选下级 BOM 信息和「查看下级配方」入口。查看使用只读面板，保留当前编辑内容；编辑下级配方仍走其自身编辑流程和离开确认。更换材料物料时清空下级配方选择，更换下级配方后须重新测算。

缺少下级配方、配方停用、循环引用等问题定位到具体行，错误路径同时标识物料和配方，例如「A［标准配方 #12］→ B［替代配方 #25］：配方已停用」。

桌面使用明细表及可折叠结构；移动 Web / PWA 使用材料卡片及逐层展开，不能要求用户靠横向滚动操作关键字段。扫码添加、物料搜索及未保存离开确认沿用现有行为。

### 4.2 备料测算

从具体 BOM 进入测算，页首展示所选配方名称及 BOM ID；从物料进入时先选择根配方。切换根配方清空旧结果。输入生产数量后，结果分为两个视图：

| 视图 | 内容 | 用途 |
| --- | --- | --- |
| 结构与各层需求 | 层级、路径、物料、用料方式、基准净用量／原分数、各层损耗、节点需求、各层配方名称／ID／编辑版本 | 核对配方和数量来源 |
| 最终领料汇总（默认） | 物料、单位、含损耗需求、账面库存、缺料、来源路径 | 备料、创建生产单 |

结构的折叠和展开只是显示操作，不改变明细行已配置的用料方式。汇总行若来自不同配方或不同损耗率，不显示虚构的「统一基准用量」或「统一损耗率」，通过来源明细查看。

页面显著显示「按毛需求展开；中间半成品库存未抵扣」和库存读取时间。改数量清空旧结果，须重新测算。检测到配方或物料信息变化时标记结果已过期，重新测算后才能建单。

### 4.3 CSV

提供「导出最终领料汇总」和「导出结构明细」，都使用当前已显示的同一份测算结果，不在导出时重新读取库存。

- 汇总表记录根配方名称／ID／编辑版本、成品、仓库、产量、库存读取时间、毛需求口径、物料需求及缺料。
- 结构表增加路径、层级、用料方式、各层 BOM 名称／编号／编辑版本、基准产量、原分数、损耗率和节点需求。
- 路径使用编码／名称及明确层级列，不能仅靠缩进空格判断。
- 保留 UTF-8 BOM、文本公式防护和分数显示规则，不导出成本。

## 5. 结构校验与变更影响

服务端是最终校验入口，前端提示复用共享规则。

| 校验项 | 规则 |
| --- | --- |
| 自引用 | 继续禁止 BOM 直接引用自身成品 |
| 配方身份 | 同物料多份配方合法；同仓库、同物料的配方名称不能重复，读写始终使用 BOM ID |
| 展开关联 | 必须显式指定下级 BOM ID，属于当前仓库，且其成品就是当前行物料；禁止自动改绑其他配方 |
| 循环 | 以 BOM ID 为图节点，沿已选展开边检查，例如 #12 → #25 → #12；错误返回物料及配方路径 |
| 重复分支 | 同一个子 BOM 被不同分支引用允许，同物料的不同 BOM 也按各自内容遍历；不能仅按物料 ID 去重或判断循环 |
| 成品回流 | 展开后最终领料项不能包含本单成品；不能通过停止展开绕过这一检查 |
| 状态与单位 | 测算／建单校验所有实际访问的 BOM、成品及材料状态和单位快照，不自动换算 |
| 不展开的配方 | 领用某物料时，不要求它自己的 BOM 存在、启用或单位已核对；只校验该物料本身 |
| 规模 | 每张 BOM 为 1–100 行，最多 10 层 BOM（根为第 1 层）、2000 个材料节点实例、500 种最终领料物料 |
| 数值资源 | 限制有理数整数位数及遍历量，超限明确报错，不能截断后继续计算 |

规模限制是运行保护，不在数据模型中固定「只有两级」。服务端、共享计算和恢复校验统一执行这些限制。

保存配方时，在事务内检查拟保存结构及受影响的上级展开链，拒绝引入循环、成品回流或超限结构；停用配方不级联停用父 BOM，允许保留无效依赖，并在父 BOM 测算／建单时指出具体原因。已停用 BOM 中的展开边也参与结构循环检查，不能靠停用绕过后再启用。

修改被选中的子 BOM 不自动改写父 BOM 的编辑版本，但必须使相关旧测算的结构校验凭证失效；同物料其他未选配方的新增、修改或停用不改变该展开链的凭证。物料停用、单位变化和子 BOM 修改均接入现有数据更新提示。

被父 BOM 明确引用的配方不能直接改绑成其他成品／半成品；须先处理上级引用。名称修改不改变配方身份。继续不增加 BOM 删除入口，停用用于保留关联和历史。

不直接修改已保存生产单；其结构和历史仍可查看。实际登记完工时继续核对实际扣库材料及成品的当前状态、单位和库存，不要求已经固化的中间节点仍可生产。

## 6. 生产单与快照

### 6.1 建单

生产单先明确选择当前仓库、目标物料的具体根 BOM，候选展示名称、ID、基准产量及状态，不按物料自动取一份。由具体 BOM 列表行或测算结果创建时带入已选根 BOM。下级配方沿用该根 BOM 各明细保存的关联，不在建单时重新自动选择。

生产预览和 BOM 测算调用同一展开引擎。保存草稿时，在一个写事务内重新校验结构凭证，并固定：

1. 根及每个展开子 BOM 的编号、编辑版本、名称、成品、基准产量及单位。
2. 每个节点的父节点、稳定路径编号、物料名称／编码／规格／单位、用料方式、净用量／原分数、损耗率及备注。
3. 最终领料物料及其所有来源路径，和按计划产量计算的汇总数量。
4. 本单支持的废料规则及其来源。

仅保存子 BOM 编号和版本号不够：当前系统没有可按旧编辑版本读取的历史配方库，因此必须保存实际内容。多份 BOM 通过不同 ID 区分；各自的版本号表示编辑修订，本期不新增历史修订发布、自动生效或自动切换体系。

草稿创建后，修改计划产量、带出本批标准耗料、耗料差异分析均只使用本单结构快照。原 BOM 改名、改用量、改用料方式或停用均不改变已有单据。

已有草稿不直接更换根配方或下级配方；需要换配方时另建生产单，并按现有规则处理原单。生产单列表及详情显示所用根 BOM ID 和快照名称，避免同成品的不同配方混淆。

### 6.2 完工、成本与作废

- 完工按最终领料汇总让用户填写实际耗料，同一物料只有一项实际量，不按来源路径重复扣库。
- 展开的半成品不产生中间入库／出库流水。材料成本直接结转到根成品，不生成虚构的半成品成本。
- 选择「领用本物料」的半成品，按其库存加权成本参与现有材料成本结转。用户可以使用现有独立生产单先生产它，但本期不自动建立父子单关系。
- 保留现有至少一种材料实际耗料大于零、缺料回滚、请求幂等、单据版本检查、成本守恒及财务权限规则。
- 每批标准量按本批合格产量和本单快照计算。累计标准按累计有效合格产量计算一次，不把逐批已取整标准直接相加。
- 单批／整单作废按原批次的实际领料和成本回退，不重新展开当前 BOM。
- 实际耗料只按物料汇总登记，来源路径用于解释标准量，不推测实际耗料在各路径间的分配。

## 7. 现有废料功能的第一期边界

现有废料包含「按产量」和「按指定材料实际投入比例」。多层展开后，同一材料可能来自多条路径，当前生产单只登记物料汇总实际耗料，无法知道各节点实际分配了多少，不能直接把下级废料规则套到总耗料上。

第一期建议采用以下边界，避免引入按节点登记实际耗料的另一套交互：

- 普通、不含展开的 BOM 保持现有废料行为。
- 被展开的子 BOM 及继续展开的后代必须没有废料规则；有规则时明确提示「该下级配方包含废料规则，本期请改为领用本物料并单独生产」。不能忽略这些规则后继续建单。
- 根 BOM 的按产量废料规则继续支持。
- 根 BOM 的按投入比例规则，其来源必须是直接领用的材料，且该物料不能同时由其他展开路径贡献用量。否则无法确定来源节点实际耗料，须拒绝测算／建单并定位规则。
- 根 BOM 废料物料不能与根成品、任何中间节点或最终投入材料重合，继续保留比例合计、单位等原有校验。

上述规则在选择展开、保存、测算和建单时都校验；以后子配方新增废料也会使新的父配方测算失败。已有生产单继续使用自己的快照。

如果第一期必须同时支持多层废料，需要增加按来源节点登记／确认实际耗料与废料的设计，再扩大本期范围，不能只做废料数量汇总。

## 8. 数据与接口设计

### 8.1 持久数据

| 数据 | 建议变更 |
| --- | --- |
| `boms` | 移除 `UNIQUE(warehouse_id, product_id)`，保留按仓库／物料查找的索引；增加同仓库、同物料、规范化名称的唯一约束，保留原 BOM ID 和各自编辑版本 |
| `bom_items` | 增加 `usage_mode: stock / explode`，默认 `stock`；增加 `child_bom_id`，仅 `explode` 必填 |
| `production_orders` | 增加配方快照格式标记，区分原单层快照及新的多层快照 |
| 新增 `production_bom_nodes` | 保存第 6 节的节点内容、父子关系和来源 BOM 信息；节点关联生产单，不能只存对当前 `bom_items.id` 的引用 |
| `production_items` | 继续作为唯一的物料耗料汇总；多层模式由节点快照生成标准量，与旧单层基准字段的计算路径显式区分 |
| 批次及废料记录 | 沿用现有按物料的实际量、成本、差异原因和支持范围内的废料规则 |

生产材料原有单层基准字段不能表达多条路径及多层损耗，不能拿取整后的「折合单耗」作为新计算依据。多层模式 API 对不适用的基准净用量／原分数／统一损耗率返回 `null`，前端显示「查看来源」；旧单层数据仍按原字段返回和计算。数据库迁移同步允许这些不适用字段为空，并按快照格式严格校验，禁止用 0 或伪造数值填充。

移除旧唯一约束时需迁移表结构并保留现有主键、外键引用、索引和版本触发器，不得通过新建 BOM ID 绕过迁移，导致已有生产单关联变化。`stock` 行的 `child_bom_id` 必须为空，`explode` 行保存明确关联。

节点快照与汇总材料必须可以互相核对，调整数量时从节点重算；不把客户端提交的汇总数量当作可信配方。递归加载可按 BOM ID 缓存配方，但每次引用仍生成独立路径节点，不能按物料 ID 缓存或合并不同配方。新节点表加入物料引用保护、删除顺序、全局重置和更新提示。

### 8.2 接口与并发

复用现有 BOM、测算及生产单接口，新增字段和显式结果格式：

| 接口 | 变更 |
| --- | --- |
| BOM 列表／生产可用配方列表 | 沿用 `product_id` 等筛选并分页返回全部匹配配方，不再假定物料唯一对应一份 BOM；生产配方列表支持同样的物料筛选 |
| BOM 新建／编辑／详情 | 允许同物料多份独立 BOM，校验名称；材料行增加用料方式、明确的下级 BOM 编号及关联概要 |
| `/api/boms/:id/calculate` | 新客户端声明 `schema_version: 2`；返回 `nodes` 结构明细、`rows` 最终领料汇总、`scraps`、`captured_at` 和 `structure_token` |
| `/api/production-orders/prepare` | 使用相同展开结果及结构凭证，仍只要求生产单权限 |
| `/api/production-orders` | 多层建单提交服务端生成的 `structure_token`；事务内重新展开、比对后保存节点快照 |
| 生产单详情 | 返回快照格式、节点及来源，按财务权限过滤成本 |

`structure_token` 是服务端对仓库、明确选中的根及各层 BOM ID／内容／编辑版本、用料方式、涉及物料的状态／单位以及数据恢复代次生成的校验凭证；客户端不能自行指定或替代配方。未选中的同物料配方不纳入凭证。它不包含库存数量：建单会重新读库存，库存波动不等于配方变化，仍不预留库存。

子 BOM 在测算与建单之间变化，即使根 BOM 的 `version` 没变，也返回 409，要求重新预览并保留本地数量、备注。同一请求已成功后的幂等重试优先返回原生产单，不能因随后配方变化重复建单或拒绝原成功结果。

整个展开过程在同一数据库读取快照内完成；建单的校验及保存处于同一写事务，不能在递归各层时分别读取不同时点的数据。

### 8.3 旧客户端及 PWA 缓存

- 旧客户端省略用料方式：新行默认 `stock`，编辑已有行按物料 ID 保留原方式和下级关联；不能重置为直接领用。明确切换为 `stock` 才清除下级关联。
- 旧客户端不声明新结果格式，遇到多层测算、预览或创建生产单时返回 409 和更新页面提示，不能偷偷返回不同语义的单层结果。
- 旧客户端对新多层生产单发起编辑、完工等操作时要求声明快照格式支持；没有能力标记则拒绝并提示刷新，防止只显示部分信息便提交。
- 无展开的 BOM、原单层生产单及其 API 行为继续兼容。
- 旧接口也按传入的具体 BOM ID 读写，不恢复「按物料任取一份」的逻辑。旧前端需要刷新后才能使用新增的同物料复制和下级配方选择交互。
- PWA 更新须包含新页面及计算模块；继续采用现有联网记账方式，不新增离线生产写入。

## 9. 权限与 AI 助手

不新增业务权限。「BOM」继续管理维护、查看、测算和导出；「生产单」用户可以预览并使用配方，包括下级必要内容，不因此取得 BOM 编辑权限。资源始终限定当前仓库。

AI 同步范围：

- `search_boms` 去掉「单层」描述，返回同物料的多份配方及各自 ID／名称／状态；`get_bom` 按明确 BOM ID 返回明细用料方式和下级关联。
- 用户只指定成品／半成品且匹配多份配方时，助手列出候选并要求明确配方，不自动选第一份或最新一份；用户已指定根 BOM 后，下级沿其已保存关联执行，不额外猜选。
- `calculate_bom` 直接调用新的服务端展开引擎，返回中间需求、最终领料、库存、缺料及计算口径，不能让模型自行递归估算。
- 生产单查询读取该单结构快照，不能用当前 BOM 替换历史内容。
- 助手说明明确毛需求、不抵扣中间库存、展开节点不单独入库、废料边界；不把测算说成已领料／已建单。
- 保持 AI 只读查询范围，不增加 BOM 或生产单写入工具，不返回财务成本。
- 核查 `src/AiAssistant.jsx` 的结果展示，确保用料方式、路径和空基准字段正确显示；没有新增写操作，因此不新增确认卡片。
- 同步 `tests/ai.test.js` 的工具数据、规则说明、权限和快照测试。

## 10. 迁移、备份与恢复

本功能业务备份格式为 32；兼容此前格式 1–31，沿用格式 31 的内扣法／外包法。

- 原 BOM 保留原 ID、名称、编辑版本和生产单关联；移除每物料一份的唯一限制。原材料行补为 `stock`，不根据物料是否有 BOM 自动推断。
- 原生产单保持单层快照格式，原材料、损耗、批次及成本不重算，不从今天的 BOM 补造历史节点。
- 新备份包含用料方式、下级关联、快照格式、节点快照及汇总材料；完整数据库备份自然包含新增内容。
- 恢复允许同仓库、同物料有多个不同 ID 的 BOM，按配方名称唯一规则校验；所有下级关联精确恢复到原 BOM ID，不因物料相同而合并配方。
- 恢复按新格式严格校验字段、仓库及物料关联、选定的下级 BOM 关联、展开图、节点树、数量、快照格式、材料汇总及批次成本守恒。
- 当前配方允许因主动停用／单位变化而暂不可用，恢复不能仅因这一状态拒绝合法备份；结构必须安全，后续测算继续按状态阻止。历史节点依据单据自身快照校验，不强求与当前 BOM 内容或版本相等。
- 原格式 1–31 补充直接领用和旧快照标记；新格式缺少必填结构不能降级为单层恢复。
- 恢复不重放库存；BOM／生产单版本及结构凭证按恢复代次失效。更新预览失效检测、引用保护、清理顺序及恢复测试。

## 11. 验收标准

| 场景 | 预期 |
| --- | --- |
| 原 BOM 升级 | 全部直接领用，分数、损耗、废料、生产及导出原结果不变 |
| 同物料多份 BOM | 成品及半成品均可新建／复制多份，各自启停及编辑；同仓库、同物料下同名拒绝，不再因已有配方而拒绝新增 |
| 明确选择根配方 | 物料详情展示全部配方，测算及生产单使用所选 BOM ID，不自动取第一份 |
| 明确选择下级配方 | 同一 B 的不同配方可被不同父 BOM 分别绑定，结果按选中配方计算；缺失、停用及物料不匹配时拒绝，不自动替换 |
| 未选配方变动 | 新增、修改、停用同物料的其他配方，不改变已选展开链、结构凭证及已有生产单 |
| 配方身份与循环 | 遍历及循环判断按 BOM ID，合法多配方及重复引用不误报，真正的 BOM ID 环被拒绝 |
| 同一半成品两种方式 | 分别生成半成品领料或下层领料，不因存在子 BOM 自动展开 |
| 两级、三级及更多层 | 各层基准产量、原分数和损耗均参与计算；结构与汇总可追溯 |
| 精确比例 | B 需求为 `1/3`、B 每 1 个用 C 3 个时，C 需求恰为 1，不因中间舍入变为 1.000002 |
| 多路径汇总 | 两条路径各需 C `1/3`，汇总为 0.666667；只抵扣一次 C 库存 |
| 半成品有库存 | 展开方式仍按毛需求计算；直接领用方式按半成品库存计算缺料 |
| 重复子树及循环 | 合法复用可算，循环、自引用及成品回流被拒绝且提示路径 |
| 下级缺失／停用／单位变化 | 不静默回退，测算及建单指出问题节点；普通直接领用不检查未使用的子 BOM |
| 测算后子 BOM 修改 | 根版本未变也不能按旧预览建单，返回 409，输入保留 |
| 保存后修改源配方 | 草稿调整产量、分批标准量和累计差异仍使用原节点快照 |
| 分批完工／作废 | 只对最终领料扣库及回退，无中间半成品流水，成本守恒且幂等 |
| 废料边界 | 支持的根规则沿用原行为；不支持的下级或来源规则明确拦截，不漏计废料 |
| 导出 | 汇总与结构来自屏幕同一结果，保留分数、路径及公式防护 |
| 权限 | 生产人员可使用配方；无 BOM 权限不能维护；无财务权限无成本泄漏；跨仓库拒绝 |
| AI 多配方消歧 | 只给物料且匹配多份 BOM 时列出候选，不猜选；查询及测算按明确 ID 进行 |
| 旧客户端／PWA 缓存 | 单层保持兼容，多层操作要求新格式，不以旧界面提交错误耗料 |
| 备份恢复 | 同物料多配方及精确下级关联往返一致，旧格式迁移保留 ID 及历史，篡改节点／关联／数量被拒绝 |
| 桌面及移动 | 桌面、Android 浏览器、iOS Safari、已安装 PWA 可编辑、测算、导出、建单及分批完工 |

开发验证复用并扩充 `tests/bom.test.js`、`tests/production.test.js`、`tests/ai.test.js`、备份断言，以及 `tests/browser/bom.spec.js`、`tests/browser/production.spec.js` 和 AI 浏览器测试。共享计算测试重点验证精确值及汇总顺序，浏览器测试验证两端实际交互。

## 12. 建议实施顺序

1. 同物料多配方、明确配方关联、共享展开模型、精确计算、结构及规模校验；数据库迁移与旧数据兼容。
2. BOM 列表及复制、根／下级配方选择、结构测算、两种 CSV、桌面和移动交互。
3. 生产结构快照、预览凭证、按快照重算、分批及作废适配。
4. AI、权限过滤、引用保护、备份恢复及数据更新提示同步。
5. 完整回归并同步现有 [BOM 使用文档](bom.md) 和 [生产单使用文档](production.md)。

各步骤属于同一期交付；在生产单、旧客户端和恢复兼容完成前，不开放新的「展开下级 BOM」写入入口。
