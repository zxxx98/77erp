# 我的待办与审核通知

桌面 Web、移动 Web 和 PWA 共用账号级待办与通知。仓库、生产两个工作区都有“我的待办”入口；仅生产岗位也可进入。

待办汇总所有仓库中的普通出入库、生产领补退料、成品及半成品入库，以及需要当前账号验收或结算的生产登记。出入库需要 `stock_approve`；登记结算需要 `production`；工序验收需要 `operation_accept` 和对应生产单的访问权限。进入单据时切换到所属仓库，并复用原来的审核页面及服务端校验。

## 通知行为

- 登录后读取提醒，前台每 15 秒检查一次，窗口重新获得焦点、恢复网络或本地业务操作成功时也会检查。
- 多条新待审核、新审核通过记录合并到一个右下角面板。事项被撤回或处理后移出待办；尚未确认的申请通知继续保留，并标记申请已处理。
- “查看待办”、刷新和退出登录均不确认通知。“我知道了”在服务器保存当前账号的确认记录，其他设备和浏览器也会生效。
- 确认仅覆盖面板读取时的事件编号上限，期间新到的通知会保留；确认失败保留面板并支持重试。
- 审核通过通知按提交账号 ID 发送，不依赖姓名。生产材料分批出库在整单完成时通知。

## 接口与存储

- `GET /api/todos?q=&offset=0&limit=20`：按权限查询待办，支持搜索和分页。
- `GET /api/todo-notifications`：返回未确认的分类数量、最近五条摘要及 `through_id`。
- `POST /api/todo-notifications/acknowledge`，正文 `{ "through_id": 123 }`：幂等确认当前账号有权读取的通知。

`todo_events` 由业务表触发器写入，与原业务事务一起提交或回滚。`todo_acknowledgements` 保存账号确认记录，不使工作区业务数据版本失效。通过请求的异步上下文记录只保存姓名的生产单据提交账号；审批登记衍生的入库单使用原登记人。删除原单据时级联清理事件及确认记录，防止业务重置、恢复备份后编号复用造成错误已读。

已有待审核单据会在初始化时纳入；不追发上线前已经完成的历史审核通知。旧生产单据只保存姓名，无法可靠还原提交账号时不猜测接收人。通知及确认记录属于运行期账号状态，不加入业务备份；业务恢复后重新生成待审核提醒。

本次没有改变业务字段、审核参数及可写业务操作；AI 助手继续调用原有业务工具，提交和确认产生的事件会跟随同一业务事务。
