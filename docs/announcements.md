# 公告系统

桌面 Web、移动 Web 和 PWA 共用一个公告中心。公告面向所有登录账号，跨仓库可见；管理员负责发布、编辑、置顶和删除，员工只能阅读。

## 第一版范围

- 公告包含标题、纯文本正文、发布人、发布时间和置顶标记。标题最多 100 字，正文最多 10,000 字，保存后立即发布。
- 列表按置顶优先、发布时间倒序展示，支持分页和只看未读。
- 打开详情并成功读取正文后，将该版本标记为已读；阅读记录按账号保存在服务端，桌面和手机同步。
- 修改标题或正文后重新变为未读；仅调整置顶不影响阅读状态。并发编辑、删除使用版本号检查，避免覆盖其他管理员的操作。
- 两端提供公告入口与未读数量；每分钟及窗口恢复焦点、重新联网时更新。离线时提示无法读取或提交。
- 删除前确认，删除后同时清除阅读记录。

暂不加入附件、富文本、定时发布、审批、推送、阅读统计和指定接收人。

## 版本更新公告

应用版本以根目录 `package.json` 为准，`shared/release-notes.json` 按版本保存更新内容。升级启动时自动向公告中心发布对应版本的更新公告，发布人显示为「系统更新」，桌面、移动 Web 和 PWA 共用阅读状态。新安装在管理员设置完成后首次读取公告时发布。

同一版本只发布一次，重启不会重复发布，也不会覆盖管理员的编辑或恢复已删除的更新公告。管理员可按普通公告编辑、置顶或删除；发布记录保存在 `release_announcements`，与公告一起包含在完整 SQLite 备份中。

## 存储与接口

`announcements` 保存公告、发布人快照、创建和更新时间、编辑版本及正文版本；`announcement_reads` 以公告和账号为联合主键保存已读正文版本及阅读时间。公告作为系统协作数据，和账号一样不参与现有业务数据导入、重置及业务 JSON 备份；完整 SQLite 数据库备份包含公告与阅读记录。

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| `GET /api/announcements` | 分页列表，可筛选未读 | 登录用户 |
| `GET /api/announcements/unread-count` | 未读数量 | 登录用户 |
| `GET /api/announcements/:id` | 公告详情 | 登录用户 |
| `POST /api/announcements/:id/read` | 标记指定正文版本已读 | 登录用户 |
| `POST /api/announcements` | 发布公告 | 管理员 |
| `PUT /api/announcements/:id` | 编辑、置顶 | 管理员 |
| `DELETE /api/announcements/:id` | 删除公告 | 管理员 |

复用现有登录、同源校验及 JSON 请求约束；服务端校验权限、字段长度、版本及分页参数。正文只以文本渲染。
