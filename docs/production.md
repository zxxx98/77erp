# 轻量生产单

桌面 Web、移动 Web / PWA 从「生产 → 生产单」进入。可从用料清单列表新建，或把备料测算中的生产数量带入新单。第一版限定当前仓库、单层 BOM、一次完工；没有在制品、分批领退料、库存预留、跨仓生产或质检自动放行。

## 使用流程

1. 选择当前仓库已启用 BOM，填写计划产量和备注。按基准产量比例计算计划用料，显示读取时的库存和缺料。缺料不阻止保存草稿。
2. 保存生产草稿。记录成品和材料的名称、编码、规格、单位、基准用量、材料备注、BOM 名称及版本快照。草稿状态显示「待生产」，不改变库存和成本。可编辑计划产量和备注；计划用料始终按本单保存的配方重算。修改或停用原 BOM 不改写既有生产单。
3. 登记完工。合格成品数量默认计划产量，实际耗料默认计划用量，用户逐项核对，可记录损耗、减少用量或把未使用材料填 0。必须有至少一种材料实际耗料大于 0，合格成品数量必须大于 0。实际材料范围固定为本单配方，不支持临时替料。
4. 确认后在同一事务内扣减实际耗料、按库存加权成本分摊材料价值，再把全部材料成本和合格成品数量一起转入成品库存。仅计材料成本，不计人工、制造费用和在制品。任一材料缺料、停用、单位变化，或成品库存／成本超限时整单回滚。数量支持最多 6 位小数；计划用料沿用 BOM 的整数百万分之一计算并最终向上取整，实际耗料不自动取整。
5. 已完工单只读，保留计划与实际数量、材料成本、创建／更新／完工／作废操作人和时间。物料操作记录展示生产耗料、成品入库及作废反向记录。数量变化接入既有低库存、缺货和库存恢复通知，不计入采购销售或应收应付。

## 作废和权限

「生产单」权限独立于「用料清单」、采购、销售和盘点。生产员工可选择已启用配方并保存草稿、完工，无需获得 BOM 维护权限。

作废另需「单据纠正」权限，必须填写原因并在页面二次确认。待生产单作废不影响库存；已完工单按原数量和原成本扣回成品、退回材料，同时保存原完工记录。成品库存或价值不足、回退使材料库存超限、零库存残留价值、物料单位变化时拒绝，并回滚全部变动。停用物料允许按原单位回退。后续交易改变成本后，即使数量足够，也可能无法按原成本作废；须先核对后续业务。

财务字段仅对有「财务管理」权限的用户返回，包括写入重试返回的结果。其他用户只能看到数量和业务记录。所有资源均按当前仓库隔离。

## 并发、备份及历史

写操作使用现有用户隔离的请求标识；同一请求重试返回原结果，不重复扣料、入库或回退。编辑、完工、作废均检查生产单版本；冲突保留本地输入，用户重新读取后核对。建单校验选择时的 BOM 版本。版本序列持久保存，重置／恢复不会让旧页面覆盖新单。

业务备份格式 24 包含 `production_orders` 和 `production_items`，格式 1–23 恢复为空生产单。恢复校验仓库、BOM、物料关联、状态／时间／操作人、唯一材料、数量及材料与成品成本合计，直接恢复库存与记录，不重放完工。生产单变化会使旧恢复预览失效；恢复后重新分配编辑版本。SQLite 完整备份自然包含新表。

被生产单引用的物料禁止删除，可停用。含生产单的仓库禁止删除以保留历史；全局业务重置会在删除 BOM 和物料前清理生产单。

## AI 助手

同时具有「AI 助手」和「生产单」权限时可用 `search_production_orders`、`get_production_order` 只读查询实际单据和保存的配方，区分待生产、已完工和已作废。不返回成本，不产生写入卡片，关闭 AI 写操作后仍可使用。AI 不创建、编辑、完工或作废生产单，也不能用采购、销售、盘点替代生产记账。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/production-orders?q=&status=&offset=&limit=` | 搜索及分页，状态 all / draft / completed / void |
| GET | `/api/production-orders/boms?q=&offset=&limit=` | 可用配方搜索，生产权限即可读取，不授予 BOM 维护权限 |
| POST | `/api/production-orders/prepare` | 只读备料预览，参数 bom_id、bom_version、planned_quantity |
| POST | `/api/production-orders` | 保存草稿，上述参数加 note、request_id |
| GET | `/api/production-orders/:id` | 单据快照及当前物料库存、状态、单位 |
| POST | `/api/production-orders/:id` | 编辑草稿，planned_quantity、note、version、request_id |
| POST | `/api/production-orders/:id/complete` | 一次完工，completed_quantity、items: [{product_id,quantity}]、version、request_id |
| POST | `/api/production-orders/:id/void` | 作废及必要的库存回退，reason、version、request_id |

验证：`node --test tests/production.test.js tests/ai.test.js`，`npx playwright test tests/browser/production.spec.js`。测试使用独立内存数据库和模拟 AI，覆盖桌面、iPhone 用户代理、启用 Service Worker 的移动 PWA、缺料回滚、精度／成本守恒、重复提交、权限隔离、并发、作废、配方快照、备份与恢复。
