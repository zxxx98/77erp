# 同一生产单内的子 BOM 分层登记

日期：2026-10-24。状态：用户已确认业务方向，书面设计待审阅；尚未实现。

## 1. 已确认的需求

在一张主生产单内，先登记各子 BOM 的半成品产量、实际耗料与进度，再登记上层半成品或最终成品。用户明确选择：半成品留在本单供上层使用，不进入仓库库存。桌面 Web、移动 Web 和 PWA 使用相同规则，生产登记岗位也能使用。

例如 A 每件需要 B 两件，B 每件需要原料 C 三件。安排 A 十件后，先登记 B 十二件、耗 C 三十六件，再登记 A 五件、耗 B 十件：B 显示已完成十二、已使用十、可用二；A 显示已完成五。C 只在登记 B 时从本单已领材料中消耗，登记 A 不重复扣 C。A 的入库仍由仓库审批。

## 2. 方案选择

| 方案 | 行为与取舍 |
| --- | --- |
| 单内分层生产（采用） | 各层保存产量、投入、批次和成本，在单内流转半成品；与用户确认的作业方式一致，需要增加单内半成品账。 |
| 自动拆分子生产单并入库 | 可以复用独立生产单和仓库流程，支持其他生产单领用，但每层增加入库、领料和审批，不符合本次选择。 |
| 只记各层进度 | 改动较少，但无法准确记录已经消耗的原料及剩余半成品成本，不满足实际耗料需求。 |

本设计只覆盖第一种方案。不增加独立子生产单、跨单调拨半成品、分层派组、工时或工资功能。

## 3. 层级与配方快照

- 每张分层生产单有一个根生产层；每个 `usage_mode=explode` 的节点生成一个半成品生产层。层级身份使用“生产单 ID + 快照路径”，根路径为空字符串。
- 同一半成品、同一子配方通过不同路径重复出现时分别登记、分别供其直接上层使用，不按物料 ID 合并半成品余额。界面显示完整路径消歧。
- 每层仅处理其直接材料：`stock` 行从整单已领材料池消耗；`explode` 行从对应下层的已登记可用半成品中消耗。
- 保存各层产品、单位、取整规则、配方编号、修订、基准产量和损耗方式。所有登记使用本单快照；后续修改 BOM 不改变在制单。
- 各层计划数量从现有精确展开结果取得，包含上层该材料行的损耗与中间物料取整规则。登记某层时，其标准投入只按该层直接配方及该层实际产量计算，不重复展开并扣除下层原材料。
- 保留十层、两千节点和五百种最终领料材料的现有限制。

## 4. 开工、分批登记与流转

### 4.1 整单领料

沿用整单最终原材料汇总领料。开始生产生成待批准领料单；仓库确认后进入生产中。补料和退料继续使用现有流程，退料仅限未投入生产的原材料。

整单原材料余额改为：已批准领料 − 已批准退料 − 所有有效层级批次的直接原材料投入。半成品内部流转不增加原材料投入，也不产生仓库库存变动。

### 4.2 登记一层

1. 选择具体生产层，填写本批合格产量，查看并核对该层直接材料的标准量、实际量和差异原因。
2. 原材料实际投入不得超过整单已领可用余额；半成品实际投入不得超过对应下层可用余额。余额不足时显示缺少的物料及来源层。
3. 每条需要下层半成品的行必须填写正数实际投入，确保不能跳过下层生产。直接原材料允许实际投入为零，整批实际投入合计必须有正数；不跨单位合计显示。
4. 产量可以小于或超过该层计划，超计划明确提示，但不自动结束生产。实际耗料可以偏离标准，保存逐项原因；不足不能用负余额放行。
5. 半成品登记增加本层单内可用数量与成本，不生成入库单，也不调用仓库库存增减。
6. 根层登记消耗直属材料与下层半成品，生成现有成品完工批次及待批准入库单；仓库批准后增加成品及根层入库废料库存。

半成品余额按生产批次保留。上层消耗时按有效批次登记顺序分配（先登记先使用），允许一次使用多个批次。分配结果持久化，后续作废必须按原来源恢复，不按当时余额重新分摊。

每层显示计划产量、累计合格产量、已供上层数量、可用数量、尚未达到计划的数量，以及批次记录。累计产量达到计划只是进度，不自动关闭该层。只有根层产量计入主生产单累计成品数与已入库数。

### 4.3 数量与损耗

人工录入继续最多四位小数，按物料取整规则规范化；默认实际投入按现有 `materialQuantity` 规则取整并明确显示。BOM 分数和逐层损耗继续精确计算，标准展示及内部追溯使用现有六位存储精度。不能把中间展示值重新作为原配方精确值。

分批取整造成的额外实际领料需求沿用补料流程，不悄悄抬高已批准领料或改写计划。累计标准按该层累计产量重新计算一次，不把逐批取整后的标准量相加。上层半成品标准投入按上层材料行损耗计算，下层生产标准按下层配方损耗计算，各条边只计算一次。

## 5. 成本与统计

半成品在单内有成本余额，但没有仓库库存成本。每次直接耗料按原材料池当前剩余数量和成本分配；每次使用半成品按所分配来源批次的剩余数量和成本分配。金额使用整数分，全部用完时带走余下成本，避免产生零数量非零成本。

每个层级批次保存投入来源及其成本，并保存可追溯到最终领料材料的组成。上层分配同时保存原材料组成的数量和金额份额；数量以百万分之一单位分配，金额以分分配，尾差留在剩余部分，最后一次消耗带走余量。分配后的组成金额之和必须等于本次分配成本，不能对每个组成项独立四舍五入后产生差额。

两种统计口径必须分开：

- 整单实际原料投入：所有有效层级批次的直接原料投入，包含仍留在半成品中的材料。用于可退料余额和整单材料使用情况。
- 根层完工成本与材料归属：已流转至最终成品批次的材料份额。用于成品入库成本和最终成品耗料分析，不能把剩余在制半成品成本提前计入成品。

`production_orders.completed_quantity`、`total_cost_cents` 继续只汇总有效根层完工批次。分层单的整单直接投入与在制成本另设明确字段，原料余额不得通过根层批次的追溯材料再次扣减。分层单涉及 `production_items` 与批次汇总的校验须按新流程分支处理，不能沿用“全部已耗成本等于根层完工成本”的旧假设。

成本守恒：已领材料成本 − 已退材料成本 = 未耗原料余额成本 + 各层未耗半成品成本 + 有效根层完工成本。最后一项同时包含待入库和已入库批次，入库审批不重复计算生产成本。

## 6. 作废、结束及余料

- 半成品批次未被任何有效上层批次使用时，可由有生产管理与单据纠正权限的用户作废，恢复其原始投入数量和成本。
- 已被上层使用（包括部分使用）的半成品批次不允许直接作废。返回依赖的上层批次编号，须先逐层撤销这些上层批次；不自动连带作废。
- 根层批次作废沿用待入库取消、已入库按原数量原成本回退的规则；已入库回退仍要求仓库入库权限。随后按原分配恢复直接原材料及半成品来源余额，不把全部原材料恢复到池中。
- 结束生产要求已有有效根层产出、没有待批准材料申请，并且所有半成品可用余额为零。未达到计划也可结束，成品待入库不阻止结束；未耗原材料继续允许结束后退仓。
- 若仍有半成品，列出具体层及剩余数量，保持生产中。本期不增加余半成品入库、跨单使用或报废处置；不得用虚构耗料或撤销真实生产来清空余额。需要继续按实际情况消耗，或在真实登记错误时走纠正流程。
- 整单作废前必须自上而下撤销全部有效生产批次，取消待批准单并退完原料；半成品从不直接退回仓库。

## 7. 页面、扫码及权限

生产详情增加“分层生产”区域，树形结构按快照路径展示各层及进度。桌面沿用现有结构浏览与详情布局；移动 Web/PWA 使用逐层进入、面包屑和卡片，登记字段不依赖横向滚动。列表可显示已开始层数与总层数，主产量始终只表示根层成品。

点击“登记”先选择成品或半成品层，显示当前层名称和路径，再填写产量与直属投入。投入分为“已领原材料”和“本单半成品”，显式标明来源及可用量；切换层时处理未保存内容。按本批产量带出耗料仍需用户核对。半成品提交按钮为“登记本批半成品”，不提供结束整单的按钮。

生产单 PDF 与二维码继续指向同一主生产单；分层单扫码后进入层级选择，不直接打开根层登记。PDF 明示“扫码后选择成品或半成品登记”，避免旧提示造成误操作。无需新增每层二维码。

各层继承主生产单的生产组，不单独派组。本组登记人员可查看和登记本组生产单的全部层级，无结束、作废、领退料或入库审批权限。新增接口须同步岗位白名单，并在幂等结果返回前核对仓库、生产组及岗位权限。成本字段（含嵌套来源和分配记录）按现有财务权限递归过滤；仅生产作业账号仍不读取仓库库存。

## 8. 数据与模块边界

新增 `stage_workflow` 标记：旧单为 0，新分层单为 1，独立于配方 `snapshot_format`。建议将分层写入和核算实现放在 `server/production-stages.js`，共享计算放在 `shared/production-stages.js`，页面层级登记放在独立组件；`server/production.js` 负责协调原有单据生命周期。

数据实体及唯一性：

| 实体 | 保存内容与约束 |
| --- | --- |
| 生产层 | 所属单、路径、父层、产品与配方快照、计划数量；单内路径唯一。 |
| 层级批次 | 所属层、批次号、产量、成本、状态、登记人及组快照、作废记录；层内批次号唯一；根层批次唯一关联现有成品批次。 |
| 批次投入 | 直接材料节点路径、投入种类、实际数量、成本、差异原因；同一批次输入节点唯一。 |
| 半成品分配 | 消耗方投入、来源层级批次、分配数量与原成本；须同单且来源为输入对应的直属子层。 |
| 原料组成及分配明细 | 每个批次及流转分配对应的原料数量和成本，用于守恒校验、根层批次追溯和原值回退。 |

原有 `production_batches` 和入库单继续承载根层完工事实。半成品批次不得混入现有成品批次列表，否则 `receiptQuantities` 会把半成品误算为已入库成品。根层批次和对应层级批次在同一事务内创建、更新或作废，两者数量、成本和状态必须一致。

读接口沿用生产详情，增加 `stage_workflow`、层级汇总与分层材料余额。批次历史按层分页读取，避免十层、大批次详情一次返回全部分配明细。新增写接口表达“指定层登记”“层级批次作废”“草稿启用分层”；根层入口统一调用分层核算，禁止经旧 `/complete` 绕过半成品余额校验。

所有写操作使用现有事务、幂等键、单据版本与快照协议校验，并显式要求客户端声明支持分层流程。任意一层登记、回退或材料余额变化都推进主单版本；过期提交保留输入并提示重新读取。跨仓、错误路径、来源伪造、过量消耗、非有限数、超精度、停用物料、单位或取整规则变化均由服务端拒绝。每层最多 1000 批，全单最多 10000 个层级批次（含作废），达到限制时明确提示，不生成部分记录。

## 9. 迁移、兼容和关联功能

- 新建包含展开节点的生产单启用分层流程；纯单层生产单继续沿用现有流程。
- 旧生产单不自动转换或推算历史半成品进度。新材料流程下尚未开工、没有任何材料单、登记批次或入库记录的多层草稿，可由管理人员明确启用分层，使用原有快照创建生产层，不读取当前 BOM 重建。
- 其他旧单显示旧流程说明并继续原有登记，历史库存和成本不重算。旧客户端对分层单的写操作收到刷新提示，不能静默按旧流程记账。
- 迁移可重复执行，失败回滚。业务备份新增全部分层实体和版本升级，旧备份默认关闭分层；恢复时校验层级关系、分配归属、状态依赖、数量与成本守恒及根批次关联。
- 同步清空数据、整单删除、仓库删除、物料与 BOM 引用保护、操作记录及数据更新通知。删除仅清理已作废生产单关联记录，不再变动库存。保持现有跨实例恢复的生产组身份处理。
- `server/ai.js` 同步查询结果及解释：半成品单内余额不等于仓库库存；子层完成不等于整单完成或成品入库；分层耗料与根层归属需区分。AI 保持只读生产查询，不执行登记、作废、结束或审批。按实际字段检查 `src/AiAssistant.jsx`，并补充 `tests/ai.test.js`。
- 保留现有下级 BOM 含废料规则时拒绝展开的限制。根层废料沿用现有 output/input_ratio 规则与零成本政策；比例来源必须为根层直接领用且唯一的原材料，不用下层耗料冒充根层投入。

## 10. 验收与验证

1. 示例 A/B/C 按先半成品后成品分批登记，逐步核对产量、原材料余额、半成品余额、入库单和成本；仓库半成品库存始终不变。
2. 三层以上嵌套、重复配方的不同路径、同物料既直接领用又经下层展开，验证来源隔离和原料只扣一次。
3. 部分使用、跨多个来源批次使用、不同成本来源、分与微量尾差、成本为零、多批进度、超计划及低于计划结束；验证数量成本守恒。
4. 下层未登记、余额不足、退料与耗料竞争、重复提交、过期版本、非法路径、错误类型和精度，失败后全部数据不变。
5. 上层依赖阻止下层作废；先作废上层再作废下层，恢复精确的原始数量与成本；已入库成品的权限与库存不足校验沿用现有规则。
6. 半成品有余额时阻止结束；半成品为零且有未耗原料时允许结束后退料；待入库成品可在结束后审批。
7. 本组登记、跨组和跨仓拒绝、仅生产作业界面、递归成本过滤、岗位变动后的幂等重放保护。
8. 新旧单并存、可用草稿显式启用分层、旧单不推算进度、旧客户端拒绝、迁移重复执行、旧备份兼容及新备份往返后继续登记和作废。
9. 桌面、手机视口及 PWA 入口覆盖选择层、登记、错误提示、未保存返回、扫码和批次作废。保留 Android 浏览器及 iOS Safari 的扫码支持。
10. 实现完成后运行 Node/API 全量测试、生产及 BOM 相关 Playwright 桌面/移动测试和构建；测试重点包含实际业务状态变化和成本守恒，不以静态字段断言代替流程验收。
