# 后处理工序

用户已确认：生产单可选绑定零到多个后处理工序；每道在绑定时填写成品系数，工艺档案不保存该系数。根据实际有效成品产量计算次数：成品生产过程中向下取整，成品完成后向上取整。各道独立计进度，工资按实际有效报工次数及单价快照计算，不重复产生产品。

- 工艺档案区分生产工艺和后处理工艺。后处理模板沿用工序名称、单价、倍率及验收模板。不能作为物料或 BOM 的生产路线。
- 生产单创建时通过 `post_processing_operations` 绑定工序，每条含 route_id、route_version、node_id、product_coefficient；正数系数最多四位小数，次数为非负整数，报工只接受正整数。
- 保留已有附加工序行为。后处理复用独立工序快照、报工、工资及权限机制，使用“次”作为单位，不继承成品单位。
- 实际有效根层成品数量达到计划数量，视为成品生产完成。未达计划时允许生产管理人员明确确认成品生产完成，释放尾数；之后停止新增产出，需撤销确认才能继续，撤销必须满足已报后处理数量不超过重新计算的上限。
- 完成前上限 floor(实际成品 / 系数)，完成后 ceil(实际成品 / 系数)；零产出上限为零。整单累计计算，不能按批分别取整。
- 所有绑定后处理工序达到最终应完成次数，且成品生产已完成，才允许结束生产；界面禁用按钮并展示未完成工序及差额，服务端同样阻止所有结束入口（含旧登记即结束入口）。未绑定时保留旧逻辑。
- 作废产出、重开、撤销完成确认不能造成已登记后处理超过新上限，须先纠正后处理记录。系数随单固定，不能修改有报工的配置。
- 数据迁移、备份恢复、工资单位、AI 只读解释同步覆盖。桌面和移动 Web/PWA共用界面和规则。

验收：计划110、系数20：实际0/19/20/39/100/101/110时上限0/0/1/1/5/5/6；分批共用上限；多个后处理均完成才能结束；少产确认尾数；越权、重复请求、作废回退、旧备份兼容、工资正确计次。
