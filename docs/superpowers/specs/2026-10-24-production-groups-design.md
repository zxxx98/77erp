# 生产组、派单和仅生产作业

用户已确认继续实施生产组和派单，并在本次增加“仅生产作业”岗位模式。

岗位决定可以做什么，生产组决定本组登记人员可以处理哪些生产单。每名员工一个岗位，可属于一个生产组，也可以不属于生产组。生产组不复制权限配置；新增多少生产组都不需要增加权限项。

保留现有“生产管理”权限的全部生产单操作范围。新增“本组生产登记”权限，仅允许所属组的生产单查询和分批登记，不允许建单、派单、领退料申请、结束或作废。未分组的登记人员看到空列表。生产管理人员在生产开始前分配或取消生产组，已开始或存在作业记录后不可改派，避免历史责任混淆。

普通岗位保留现有基础业务读取能力。“仅生产作业”模式只允许本组生产登记，前端只显示生产工作空间、修改本人密码和退出；服务端拒绝物料、库存、历史业务单据、财务、AI、公告等独立入口。生产单内保留登记必需的材料身份、配方和数量，不返回库存余额和成本。

仓管继续按“出库”审批各组领料，按“入库”审批各组退料和成品入库，无需所属生产组。生产组查询范围不应用到仓管审批入口。

服务端每次请求重新核对当前岗位和组；重复请求返回缓存结果前也检查授权。换组、换岗及改派使授权版本变化，浏览器移除旧作业表单，AI 会话不能沿用旧访问上下文。

启动迁移 `production_groups_v1` 在单一事务里新增生产组、员工及生产单关联、岗位访问模式和批次归属快照。原员工和生产单不自动分组，原权限不变。完成标记保证重启或重复部署不重复处理；失败整体回滚。业务 JSON 备份保留历史组名和登记人名；跨实例恢复清除组织/人员 ID，避免与目标实例的同号记录错误关联。完整数据库备份保留全部组织配置。

验收覆盖桌面和移动 Web/PWA、跨组隔离、无组空列表、真实登记、仓库跨组审批、请求重放、迁移中断/重启、旧备份和 AI 查询范围。
