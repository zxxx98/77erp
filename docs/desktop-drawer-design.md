# 桌面 Web 二级窗口抽屉化设计

日期：2026-10-19

状态：第一批已在本地实现，生产构建及相关浏览器回归通过；尚未部署

适用范围：桌面 Web；手机、平板的移动 Web / PWA 保持当前展示和交互。

## 1. 设计结论

桌面端将长表单和需要持续浏览的详情窗口改为右侧抽屉，按内容提供标准、宽两档尺寸。短表单、确认、标签预览继续采用居中窗口，完整业务工作区暂时保留现状。

第一批包括：

1. 新增 / 编辑物料。
2. 物料详情。
3. 采购、销售及调拨等现有单据详情。
4. 出入库二维码管理，包含列表、新建 / 编辑、标签、使用记录和配置修改记录。

第一批仅调整上述窗口的容器、内容排版及必要的关闭保护，不改变业务接口、数据结构、权限、金额和数量规则，不新增业务入口。不更新应用版本号，不涉及发布。

手机和平板继续使用现有移动界面和底部弹层，不因屏幕较宽切换为桌面抽屉。桌面浏览器缩窄时仍属于桌面界面，抽屉按可用空间适配。

## 2. 问题与现状

桌面公共 `Modal` 位于 `src/components/common.jsx`，默认宽 510px，`wide` 为 800px，最大高度为 92vh。物料表单和物料详情使用默认尺寸，字段、图片、操作记录及其他仓库库存增加后，容易形成细长窗口。

当前桌面普通弹窗由容器整体滚动，标题和底栏使用 sticky；工作空间设置已有独立滚动区，宽度为 1100px，AI 助手也已有专门布局。因此，不能通过统一修改所有 `.modal` 来完成本次调整。

移动端通过 `src/device.js` 的设备识别及 `.mobile-device` 样式选择布局。`src/mobile-web/mobile.css` 已将公共弹窗展示为底部弹层，并处理安全区、键盘和视口高度。本次保留这些规则。

设计沿用 [现有设计规范](design-system.md) 的颜色、字体、按钮和间距，不引入新的视觉体系。

## 3. 窗口分类与改造范围

### 3.1 第一批实施

| 窗口 | 目标形态 | 目标宽度 | 主要原因 |
| --- | --- | --- | --- |
| 新增 / 编辑物料 | 标准右侧抽屉 | 680px | 长表单，包含图片、规格、备注和跨仓同步 |
| 物料详情 | 标准右侧抽屉 | 680px | 档案、历史记录、其他仓库存量会持续增长 |
| 单据详情 | 宽右侧抽屉 | 1000px | 明细表、收付款及纠正操作需要横向空间 |
| 出入库二维码管理 | 宽右侧抽屉 | 1000px | 多个内部视图，共用稳定的管理工作区 |

目标宽度按视口收缩，具体规则见第 4 节。只在入口显式声明抽屉类型，不按内容高度自动改变容器形态。

### 3.2 后续可评估，本批不改

| 窗口 | 后续方向 | 本批暂缓原因 |
| --- | --- | --- |
| 新建采购入库 / 销售出库 | 宽抽屉或专门开单工作区 | 模板、选品、明细及汇总需要整体重排 |
| 用户权限配置 | 设置工作区中的独立配置面板 | 当前从设置窗口打开，需统一考虑层级和返回 |
| AI 助手 | 宽侧边助手或独立工作区 | 已包含会话历史、聊天和业务表格，窄抽屉会挤压内容 |
| 工作空间设置 | 保留宽窗口，后续可评估独立设置页 | 已有左侧导航及稳定的内容滚动区 |
| 业务管理 | 优先评估独立页面 | 财务、调拨和多仓库盘点依赖较宽表格，普通抽屉不合适 |

供应商与客户、模板、财务、盘点、导入导出等目前属于业务管理内部内容，本批不拆成独立抽屉。

### 3.3 保留现有形态

| 窗口 / 内容 | 保留形态 | 理由 |
| --- | --- | --- |
| 分类管理 | 居中短表单 | 当前主要是分类选择、名称和上级分类 |
| 增加库存（退料） / 减少库存 | 居中短表单 | 核心为数量和原因，完成一次操作即可关闭 |
| 账户设置 / 修改密码、修改账号名称 | 居中短表单 | 字段少，无需满高工作区 |
| 扫出入库二维码后的执行确认 | 居中确认窗口 | 核对明细后明确提交，沿用现有库存变更流程 |
| 删除、作废、重置、提交等确认 | 原有确认形式 | 保持清晰的继续 / 取消决策 |
| 物料条码 / 物料二维码展示 | 居中标签预览 | 围绕标签查看和下载，不需要长表单容器 |
| 使用说明 | 居中窗口 | 当前篇幅短 |
| 图片预览、摄像头扫码 | 现有全屏界面 | 保留图片查看、取景及扫码交互 |
| 库存提醒、下拉菜单、选品浮层 | 贴近触发元素的浮层 | 需要保持与触发位置的关系 |
| 移动端仓库切换、本地草稿及其他弹层 | 现有移动弹层 | 不属于桌面改造范围 |

## 4. 抽屉外观与响应式尺寸

### 4.1 桌面布局

抽屉从视口右边缘进入，顶部、右侧、底部贴边，高度为 100dvh，不保留原弹窗四周的 24px 空隙。表面为白色，使用细边框和向左投射的阴影，边角不使用居中弹窗的圆角。

背景页面保留原位置并被遮罩覆盖；抽屉打开期间锁定背景滚动，禁止点击或通过键盘操作背景。第一批采用模态抽屉，不支持同时操作列表和抽屉，不支持拖动、缩放、停靠或多抽屉并排。

| 项目 | 规则 |
| --- | --- |
| 标准档 | 680px |
| 宽档 | 1000px |
| 视口宽度 ≥768px | 实际宽度为目标宽度与 `视口宽度 - 48px` 中较小者，左侧至少保留 48px 背景 |
| 桌面视口宽度 <768px | 占满视口宽度，仍沿用桌面抽屉及桌面业务组件 |
| 高度 | 100dvh，短屏也不超过可视区域 |
| 标题区 | 左侧标题与副标题，右侧关闭按钮；高度随换行自然增长 |
| 内边距 | 桌面通常为 24px；窄窗口降至 16px |
| 区块间距 | 24px；同组字段间距使用现有 12–16px 规则 |
| 动效 | 从右向左进入，约 180–200ms；减少动态效果偏好下禁用位移动画 |

例如，在 1440px 桌面视口中，标准档宽 680px、宽档宽 1000px；在 900px 视口中，宽档收缩至 852px；在 390px 的桌面视口中，两档都占满宽度。

以上断点仅控制桌面布局，不参与设备身份识别。Android 平板、iPad 即使超过 768px，也继续使用当前移动端展示。

### 4.2 固定区域与滚动区域

从上到下统一为标题区、内容区、操作区：标题和操作区不滚动，内容区占据剩余空间并允许纵向滚动。

- 抽屉及其表单使用 flex 布局；内容区设置 `min-height: 0` 和内部滚动，避免外层整体滚动。
- 表单内容较长时，保存、取消、金额汇总等主要操作始终可见。
- 表格仅在自身容器内横向滚动，不撑开抽屉，不造成页面横向滚动。
- 标签 SVG、图片和预览区域限制在内容宽度内；较长预览随内容区纵向滚动。
- 动态展开历史记录、显示错误或增加明细时，不改变抽屉宽度，不让底栏被推离视口。
- 浏览器缩放及短视口下，标题保持紧凑、操作按钮允许换行；内容仍可通过滚动访问。

## 5. 各窗口内容设计

### 5.1 新增 / 编辑物料

使用标准档，标题沿用「新增物料」「编辑物料」。内容分为三个区块，使用小标题和留白区分，不为每组额外套卡片。

| 区块 | 内容 |
| --- | --- |
| 基础信息 | 名称、条码、分类、单位、规格型号 |
| 图片与说明 | 图片上传 / 预览、备注 |
| 价格与库存设置 | 按权限显示的参考价格、安全库存、同步仓库 |

名称、条码、规格和备注占整行；分类 / 单位、参考价格等短字段可两列排列。可用内容宽度不足时改成单列；移动端继续使用当前字段顺序和排版。

底部固定「取消」「保存物料」。保留条码留空语义、图片上传限制、库存初始化规则、跨仓同步、版本冲突展示和使用最新信息重新编辑流程。

首次进入将焦点放到物料名称；服务端校验错误或版本冲突出现后，使对应错误区域可见，保留输入。图片处理或保存期间，关闭、取消和 Esc 均不能绕过现有忙碌保护。

### 5.2 物料详情

使用标准档，依次展示物料图片及名称、档案字段、当前物料操作记录、其他仓库库存及已有库存表达式结果。

档案沿用两列信息布局，规格型号和备注占整行；窄窗口降为单列。操作记录保留当前手动展开、按需加载和继续加载机制，不在打开抽屉时额外拉取全部历史。

底部固定「关闭」。查看图片继续打开现有全屏预览，关闭图片后回到详情原滚动位置。

点击操作记录中的单据，沿用当前入口切换到单据详情，不叠加第二个同级抽屉。本批不新增返回物料详情的导航栈。

### 5.3 单据详情

使用宽档，依次展示状态、往来单位 / 调拨对方、时间、物料明细、备注与开单人，以及有权限查看的收付款和单据纠正区域。

明细表格末尾固定「总计」行，显示物料种类、总数量及合计金额 / 调拨成本；底部固定物料种类及「关闭详情」。调拨仍沿用现有成本权限和从调拨记录撤销的说明，不添加收付款或普通单据纠正操作。

明细保持表格，物料名称允许合理换行，条码可横向滚动查看，金额和数量保持对齐。大量明细通过内容区滚动浏览，不压缩成不可读的小字号。

收付款、退货、作废等沿用各自的业务确认和提交行为；容器改造不引入新的自动提交、自动保存或通用单据草稿。

### 5.4 出入库二维码管理

使用宽档，列表、编辑、标签及两种记录视图共享同一个抽屉。内部切换不重复播放抽屉入场动画，不产生新的遮罩。

| 视图 | 标题 / 导航 | 底部操作 |
| --- | --- | --- |
| 列表 | 管理出入库二维码；保留筛选及新建入口 | 固定关闭；分页沿用列表区域的位置 |
| 新建 / 编辑 | 新建或编辑出入库二维码；提供「返回列表」 | 固定取消编辑、保存二维码 |
| 标签 | 出入库二维码标签；提供「返回列表」 | 固定关闭；下载等现有动作保留 |
| 使用记录 / 配置修改记录 | 对应标题；提供「返回列表」 | 固定关闭；分页随记录内容展示 |

桌面端「返回列表」放在标题区，编辑页底部「取消编辑」也返回列表；右上关闭按钮关闭整个管理抽屉。编辑取消、返回列表和关闭都受未保存内容保护。

保存按钮移动到底部时保持其与当前表单的关联，不引入嵌套表单。移动端继续使用当前保存按钮、返回入口及所在位置。

保存成功后沿用当前状态切换逻辑。首次切换内部视图时内容回到顶部；返回列表保留筛选和分页。保留至多 100 种物料、顺序调整、次数限制、二次确认、版本校验及标签下载规则。

扫码添加物料继续打开现有摄像头界面，关闭扫码后恢复编辑内容。管理抽屉与扫码后的「确认入库 / 出库」是不同入口，后者不改为抽屉。

## 6. 关闭、状态与可访问性

### 6.1 统一关闭规则

| 触发方式 | 行为 |
| --- | --- |
| 右上关闭按钮 | 请求关闭当前抽屉 |
| 底部取消 / 关闭 | 执行对应关闭或返回动作 |
| Esc | 仅当前最上层界面处理，执行与关闭按钮相同的检查 |
| 点击背景遮罩 | 不关闭，与现有公共弹窗保持一致 |
| 提交、图片处理等忙碌期间 | 保留现有关闭锁定，所有关闭入口统一生效 |
| 关闭成功 | 恢复背景滚动和触发位置的焦点；触发元素不存在时回到所在页面的合理位置 |

新增 / 编辑物料、二维码新建 / 编辑在桌面端增加未保存修改检查：只有实际修改过字段、图片或同步选择等内容，关闭或退出编辑时才提示放弃修改。初始空白表单、仅打开查看或保存成功后的状态不提示。

第一批复用项目已有的 `window.confirm` 确认方式，文案分别为「物料信息尚未保存，确定放弃修改并关闭？」和「二维码配置尚未保存，确定放弃修改？」。取消确认后继续编辑，内容和滚动位置保留；确认放弃才执行原动作。不新增自定义确认窗口及确认层级。

此关闭保护属于桌面端新增行为，不为移动端增加新的提示，也不替代移动开单已有的草稿流程。单据详情中已有的收付款、纠正输入不纳入本批通用脏数据检测。

### 6.2 焦点与层级

- 保留 `role="dialog"`、`aria-modal="true"` 以及标题关联；抽屉仍属于模态对话框。
- 长表单按业务入口设置初始焦点；只读详情优先聚焦容器，避免误聚焦下方收付款输入框而滚到中间。
- Tab / Shift+Tab 限制在最上层界面内，背景区域不可聚焦。
- 图片或摄像头全屏界面打开后，由上层处理 Esc 和焦点；一次 Esc 不得同时关闭上层和抽屉。
- 关闭上层预览后恢复抽屉原焦点和滚动位置；抽屉未关闭前不释放背景滚动锁。
- 下拉选择、搜索结果等浮层应高于抽屉内容，且不被内容区裁切；保留其定位和键盘交互。
- 移动端沿用现有浏览器返回事件及 PWA 更新时的编辑窗口检查，不改对话框识别语义。

## 7. 技术落点与兼容策略

### 7.1 公共组件

在现有 `Modal` 上增加可选参数，复用其无障碍、焦点和滚动管理，避免复制一套缺少后续维护的弹层基础逻辑：

```jsx
<Modal presentation="drawer" drawerSize="standard" {...existingProps} />
<Modal presentation="drawer" drawerSize="wide" {...existingProps} />
```

- `presentation` 默认 `dialog`，`drawerSize` 默认 `standard`，不影响旧入口。
- `wide` 继续服务现有居中弹窗；桌面抽屉尺寸由 `drawerSize` 明确决定。
- 抽屉实际生效条件为 `presentation === 'drawer' && !mobileDevice`。
- 移动端忽略新增抽屉参数，保留现有 `wide`、DOM 包装及移动样式所依赖的结构。
- 如需增加内容区包装或底部动作槽，只在桌面抽屉分支使用；共享字段重排、初始焦点和关闭保护也按桌面生效条件隔离。
- 保留既有 `.modal` 类和对话框语义，避免破坏当前最上层窗口检测、浏览器测试及 PWA 更新保护。
- 抽屉样式使用专用类并限定在非 `.mobile-device` 环境，不修改全局 `.modal-backdrop` 的默认对齐与间距。
- 背景不可交互、焦点和上层关闭处理应在实现时结合现有逻辑补齐，并验证恢复状态；不把这些能力视为当前代码已经完整具备。

### 7.2 预计涉及文件

| 文件 | 计划职责 |
| --- | --- |
| `src/components/common.jsx` | 可选展示类型、抽屉结构、焦点和层级处理 |
| `src/styles.css` | 桌面抽屉尺寸、动画、固定区域及内容响应式布局 |
| `src/features/ProductDialogs.jsx` | 物料编辑 / 详情启用抽屉，桌面字段分组及关闭保护 |
| `src/features/OrderDetail.jsx` | 单据详情启用宽抽屉 |
| `src/StockQr.jsx` | 管理入口启用宽抽屉，桌面导航、固定操作和关闭保护 |
| `tests/browser/` | 桌面抽屉行为验证及相关移动端回归 |

原则上无需调整 `server/`、`shared/`、`src/mobile-web/` 或 `src/pwa/` 的业务实现；本设计文档不产生上述代码变更。

## 8. 实施顺序

1. 增加默认关闭的桌面抽屉能力，验证未启用的弹窗及移动端仍保持原状。
2. 接入物料新增 / 编辑、物料详情，验证长内容、图片、同步仓库和关闭保护。
3. 接入单据详情，验证明细表、金额及权限相关操作。
4. 接入二维码管理，验证内部切换、固定保存、返回和扫码覆盖层。
5. 完成桌面与移动回归，提供两档抽屉及窄桌面窗口的截图供验收。

开单、权限配置、AI、设置和业务管理不在本批实现中顺带调整。若后续推进，分别补充布局设计。

## 9. 验收标准

### 9.1 桌面布局

- 1440×1000、1280×800：四类入口均从右侧打开，标准档 680px、宽档 1000px，标题及底部主要动作可见。
- 900×600：宽档收缩至 852px，表格在自身区域滚动，页面不出现横向滚动。
- 390×844 的桌面浏览器：抽屉全宽，短字段转单列，仍使用桌面业务组件，不切换移动外壳。
- 1440×600 及浏览器 200% 缩放：长内容和按钮均可访问，无重叠遮挡。
