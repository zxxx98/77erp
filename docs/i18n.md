# 多语言维护

支持 `zh-CN`、`en`、`vi`。登录页和桌面、移动 Web/PWA 外壳共用 `src/i18n/LanguageSwitcher.jsx`；国旗保存在 `public/flags/`，随 PWA 缓存。

## 新增界面文字

1. 在 `src/i18n/catalogs/` 对应模块添加稳定语义键，值固定为 `[中文, English, Tiếng Việt]`，三个译文使用相同插值参数。
2. 组件调用 `useLocale()` 订阅语言变化，以 `t(key, params)` 渲染。模块级常量保存键或使用延迟计算，避免初始化时固定译文。
3. 日期、数字使用 `getFormatLocale()`；切换语言不改变业务时区、币种、汇率或数据库值。
4. 新增词库须在 `src/i18n/index.js` 注册，并运行 `tests/i18n.test.js` 检查重复键、缺失译文和参数。

`translateText()` 仅用于明确属于系统的显示元数据。用户名称、备注、模板、历史消息等原样显示。生产类型继续存储 `成品/半成品/原料`；图表系统标签通过 `seriesLabelKey` 标记，分组标识和钻取查询保持稳定。

## 语言偏好与接口

首次访问按本地偏好、浏览器语言选择，不支持的语言回退中文。登录后优先使用待同步选择和账户语言；本地缓存支持离线选择，恢复网络后重试。跨标签页通过 storage 事件更新，不重新挂载页面。

`PATCH /api/auth/language` 只修改当前账户，接受 `{ language, user_id? }`；`user_id` 用于拒绝会话已切换时的旧请求。状态及登录响应返回 `language`。

服务端语言优先级为显式 `language` 查询参数、`Accept-Language`、账户语言、中文。接口保留原 `error`，增加 `code`、`params`、`message`；前端显示 `message`，业务分支使用稳定码。共享校验翻译位于 `shared/error-translations.js`，不要把请求语言写入服务端全局状态。

## 导出与 AI

物料、盘点、BOM 和生产 PDF 使用明确的导出语言，默认跟随界面。导入兼容原中文和新增英越文表头，并转换回原始业务字段。用户上传的品质模板保持原样。

AI 默认回复跟随界面语言，用户明确指定时遵循用户指令。工具 schema、字段名和确认载荷保持稳定，只翻译系统展示内容。修改业务字段时同步检查 `server/ai.js`、`src/AiAssistant.jsx`、`tests/ai.test.js`。

## 验证

- `npm test`：账户隔离、校验、错误翻译、导入导出及业务回归。
- `node --test tests/i18n-sync.test.js`：快速切换、跨标签页乱序响应、离线重试及账户切换。
- `npx playwright test tests/browser/i18n.spec.js`：桌面、Android/PWA、iOS WebKit、国旗菜单、表单保留和英越文业务提交。
- `npm run build`：前端构建与 PWA 预缓存。浏览器测试期间不要并发重建 `dist`。

现有中文浏览器用例显式设置 `locale: 'zh-CN'`，独立创建的浏览器 context 也要设置，避免机器语言影响测试。
