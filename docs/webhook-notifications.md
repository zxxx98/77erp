# Webhook 通知

管理员可以在网页「系统设置 → 通知设置」、手机网页「更多 → 商户与仓库设置 → 通知设置」或安卓「商户与仓库设置 → 打开通知设置」配置。当前提供一组全局 Webhook 接收配置，所有设备共用；可选择全部仓库或指定仓库、通知类型和是否显示金额。

## 配置

1. 选择通知格式：通用 JSON、企业微信、钉钉或飞书群机器人。
2. 填写完整公网 HTTPS Webhook 地址。地址中的查询参数会保留，支持自定义端口；不支持 HTTP、内网、本机地址、URL 账号密码或重定向。每次投递重新解析并校验 DNS，连接绑定至校验通过的 IP。
3. 通用 Webhook 可选签名密钥；钉钉、飞书机器人启用加签时填写其密钥。企业微信使用 Webhook 地址自带的凭据。机器人如配置关键词，可设为「77 ERP」。
4. 勾选「启用 Webhook 通知」及所需类型。所有类型默认未勾选；允许保存开启但无订阅类型的配置，此时不发送业务通知。
5. 选择仓库和是否显示金额。未选择具体仓库表示全部仓库，包含以后新增的仓库。关键管理操作始终为全局事件。
6. 点击「保存通知设置」，再「发送测试通知」。测试使用已保存的配置，不受总开关、类型和仓库筛选影响；每 30 秒最多一次。发送结果在最近记录中查看。

完整地址和签名密钥仅保存在服务器数据库，读取设置只返回地址域名和是否已配置，输入框留空保留原值。可显式清除地址或密钥；清除地址前需关闭通知。普通用户不能读取设置、投递记录或调用测试／重试接口。配置版本校验防止覆盖其他管理员的修改。

每次保存均使旧配置未完成的投递失效，包括等待重试及最终失败的记录，避免把旧消息发往新接收方。已在网络中发送的请求可能已经到达，无法撤回。

## 通知类型

| 事件键 | 触发时机 |
| --- | --- |
| `low_stock` | 库存从高于安全库存降到 `0 < 库存 ≤ 安全库存`。持续低库存不重复发送。 |
| `out_of_stock` | 库存从正数降为 0。直接从正常变成缺货只发送缺货提醒。 |
| `stock_recovered` | 低库存或缺货恢复到高于安全库存。缺货补到仍低于安全库存不发送恢复通知。 |
| `purchase_in` | 普通采购入库成功，包含套用模板及业务二维码开单。 |
| `sale_out` | 普通销售出库成功，包含套用模板及业务二维码开单。 |
| `order_return` | 采购或销售退货成功，附原单号。 |
| `order_void` | 普通单据或退货单作废成功。 |
| `transfer` | 仓库间调拨成功，或在调出仓库撤销调拨。附调出、调入仓库与物料数量。 |
| `stock_adjustment` | 有实际差异的库存盘点，或报损／减少库存成功。只读多仓库对照不触发。 |
| `payment` | 登记、撤销收付款或历史收付核对，附当前是否结清。 |
| `daily_summary` | 到达指定时间，汇总选定仓库当天经营及当前库存预警数量。 |
| `admin_action` | 业务重置、备份恢复成功，或员工权限、账号角色／状态发生实际变化。 |

开单、退货、作废、盘点和报损都检查库存状态转换。新增档案、调整安全库存、批量导入期初库存及备份恢复不会逐物料触发库存通知，避免批量消息；备份恢复只发送一条管理通知。

一张单据或一次盘点中的多个物料按事件合并发送。如果同一操作同时符合业务通知和库存通知，会分别生成事件。机器人消息仅展示前 6 种物料，超长消息会截短并提示在 ERP 查看；通用 JSON 的 `data` 保留完整明细。

关闭金额显示后，不发送结构化单价、单据金额、收付款金额和经营汇总金额，也不在自动生成的文本里显示金额。操作人自行填写的名称、往来单位、备注或原因按原文传递。通知不包含库存成本或毛利。

## 每日汇总

默认 `Asia/Shanghai` 时区、18:00，时间与时区均可修改。汇总当天零点至生成时的数据，不包含作废单据；退货按发生日冲减对应采购／销售净额，并单独列出退货金额。低库存计数不含缺货，缺货单独计数。

服务需运行才能执行定时任务。当日错过时间会在服务启动后补发一次，之前日期不补发；同一天已经生成过汇总，即使重启、修改时间、停用后重新启用或恢复业务备份，也不重新生成。汇总生成后的当日交易不会再次追加至该条汇总。

## 投递与保存

业务事件与业务数据在同一个 SQLite 事务中落库，回滚不会留下通知。普通单据、业务二维码及纠正操作的请求重放不会生成新事件。后台每 2 秒检查队列，逐条投递；网络超时或对方拒绝消息不会影响业务提交。

首次失败后分别等待 30 秒、2 分钟、10 分钟和 1 小时，最多尝试 5 次；失败记录支持手动重试。进程重启后恢复未完成记录，发送中异常退出的记录租约到期后重试。投递采用至少一次语义：接收方已处理但响应丢失时可能收到重复消息，应按稳定的事件 `id` 去重。

通用 JSON 以 HTTP 2xx 为成功。机器人格式同时检查响应体中的业务成功码，不把 HTTP 200 内的机器人错误当作成功。日志不保存对方响应正文或 URL，以免记录凭据。页面展示最近 50 条，成功及取消记录保留 30 天，失败记录保留供重试。

配置、密钥、投递队列、日志和汇总日期记录不进入 JSON 业务备份；业务恢复及重置保留这些服务器配置和记录。完整 SQLite 备份会包含它们。当前不支持多接收地址或按类型指定不同接收方。

## 通用 JSON 协议

服务以 `POST application/json` 投递，协议版本为 `1`。金额汇总使用整数分，明细中的 `price` 使用元。

```json
{
  "id": "唯一事件 UUID，重试时保持不变",
  "version": 1,
  "event": "purchase_in",
  "occurred_at": "2026-10-14T08:00:00.000Z",
  "business_name": "七七商贸",
  "warehouse": { "id": 1, "name": "主仓库" },
  "actor": { "id": 1, "username": "admin" },
  "data": {
    "order_id": 100,
    "number": "RK20261014000001",
    "type": "in",
    "kind": "normal",
    "partner": "供应商",
    "reason": "补货",
    "items": [{ "product_id": 1, "name": "物料 A", "barcode": "SKU-000001", "quantity": 5, "unit": "个" }]
  },
  "message": "77 ERP · 采购入库\n…"
}
```

全局事件的 `warehouse` 为 `null`；定时汇总的 `actor` 为 `null`。启用金额显示后，单据增加 `total_cents`，明细增加 `price`（元）和 `amount_cents`（分）；旧历史明细的行金额可能为 `null`。

请求头包含：

- `X-77ERP-Event-ID`：事件 UUID。
- `X-77ERP-Timestamp`：本次发送的 Unix 毫秒时间戳，重试时重新生成。
- `X-77ERP-Signature`：配置通用签名密钥时提供，值为 `sha256=` 加十六进制 HMAC-SHA256。签名原文是「时间戳 + 英文句点 + 原始 HTTP 请求体」，密钥为保存的签名密钥。

接收方使用原始请求体校验签名，以恒定时间比较，并检查发送时间及事件 ID，避免重复处理。钉钉使用官方时间戳查询参数签名，飞书使用官方 `timestamp` / `sign` 正文字段。

## 管理接口

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/settings/notifications` | 获取脱敏配置。 |
| `PUT /api/settings/notifications` | 保存配置；提交当前 `version`、`enabled`、`format`、`events`、`warehouse_ids`、`include_amounts`、`daily_time`、`timezone`，可选 `url`、`secret`、`clear_url`、`clear_secret`。 |
| `POST /api/settings/notifications/test` | 使用保存配置发送测试，提交当前 `version`。返回 202 和事件 ID。 |
| `GET /api/settings/notifications/deliveries` | 最近 50 条投递记录，不返回消息正文或凭据。 |
| `POST /api/settings/notifications/deliveries/:id/retry` | 将当前配置下失败或等待重试的记录重新入队。 |

这些接口均仅管理员可用。服务入口 `server/index.js` 启动及停止后台投递任务；通过 `createApp()` 嵌入服务时需调用返回的 `notifications.start()`，关闭数据库前等待 `notifications.stop()`。测试可注入 `webhookSend` 并手动调用 `notifications.tick()`，不访问真实接收方。
