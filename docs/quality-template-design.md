# 品质管理：验收单模板配置设计

数据类型新增「唯一 KEY」（`uniqueKey`）：普通字段和对象属性共用一个名额，整个模板最多配置一个，未配置时不影响保存或发布。编辑器禁用其他字段的同类型选项；修改类型或移除字段后释放名额，取消编辑保留原配置。草稿、发布、接口预览及备份恢复均执行相同校验。

唯一 KEY 按字符串规则读取 Excel 显示文本，保留编号前导零；空值由「必填」配置决定。多 Sheet 解析时按同一字段配置分别读取，各 Sheet 共用模板中的一个配置。当前只限制模板配置数量，不对对象记录、不同 Sheet 或历史验收单中的数据值增加去重约束。字段类型随现有模板版本及解析结果保存，无需数据库结构迁移。AI 未开放品质写入工具，提示说明同步此规则。

状态：桌面模板配置与验收单导入解析已实现，含模板版本绑定、结果预览、错误定位、确认保存及原文件下载；图表配置与展示已实现，详见 [品质图表设计](quality-charts-design.md)。日期：2026-10-20。模板仍只配置单个 Sheet；验收导入支持多个数据 Sheet 复用同一套模板规则。

验收单导入解析的最终实现见 [验收单导入设计](quality-acceptance-design.md)。下文第一阶段范围及后续建议以阶段划分阅读。

## 1. 目标与阶段

整体流程为「上传原始 Excel → 配置字段读取规则并保留原文件 → 用户下载 Excel 填写 → 上传填写后的 Excel → 按对应模板规则解析 → 根据结构化数据生成图表」。本期交付第一阶段：把固定版式 Excel 配置成可保存、可下载使用、可验证的验收单模板。

第一阶段包含模板列表、上传并保存原始 Excel、选择工作表、表格预览、手动添加普通字段、通过分步框选添加对象 Key、字段规则、样表解析预览、草稿、启停、发布版本和下载已配置模板对应的原始 Excel。样表预览用于验证配置，不生成正式验收记录。模板来源仅为上传 Excel，不提供从空白网页新建表格或用 JSON 替代原始文件的入口。

本期范围按用户明确要求限定为桌面 Web：手机端不开放入口，不做移动 Web / PWA 适配。本约定覆盖仓库默认两端开发与验收要求，仅针对此次模板配置功能；后续验收单接收与图表功能的终端范围另行确定。

后续第二阶段实现用户上传下载后填写的 Excel、人工选择模板及版本、版式校验、解析结果复核与入库；第三阶段实现按日期、供应商、物料等维度统计的图表。第二阶段起使用用户明确选定的模板及版本，不引入自动识别模板或区域的依赖。

模板由「原始 Excel 文件 + 字段读取规则」共同组成。原文件完整保存在项目当前备份所配置的 R2 存储桶，Excel 使用独立目录前缀，默认 `excel`，可由管理员填写。下载直接返回 R2 保存的原文件字节，保留其中全部工作表、格式、图片、内嵌图表、公式及打印设置；字段配置不改写原文件。网页表格只是配置时的预览。

本期按固定位置的表单设计，支持普通字段和重新设计的对象 Key。对象 Key 通过用户明确框选属性行和值区域表示一组明细，每个数据行对应一个对象，解析为对象数组，用于后续图表。属性默认字符串，不按内容推断类型。本期不实现对象嵌套、自动寻找明细结束行、跨表关联、OCR、PDF/图片识别、公式计算或完整 Excel 在线编辑器。

## 3. 入口和页面

### 3.1 入口

桌面主导航新增「品质管理」，第一阶段进入「验收单模板」列表。手机端不增加入口。模块需要独立页面，避免在已有业务弹窗中继续嵌套大型表格编辑器。第一阶段只显示可用的模板功能，不放置无法使用的解析、图表页签。

模板默认属于当前仓库；切换仓库前处理未保存修改。后续若需要复用其他仓库规则，通过复制模板实现，不隐式共享可修改配置。

### 3.2 模板列表

列表展示名称、原始 Excel 文件名、工作表、字段数、状态、启用版本、更新人和更新时间；支持搜索名称和按状态筛选。操作包括上传 Excel 新建、编辑、复制、下载 Excel、启用/停用。第一阶段用停用保留配置，不提供物理删除。普通下载使用当前已启用版本绑定的原文件；维护人员可以在版本详情中下载对应历史文件。

模板由仓库内具有品质权限的人员协作维护，不沿用现有开单模板的私人归属限制。创建人、更新人用于追溯。

### 3.3 桌面编辑页

- 页首：返回列表、模板名称、状态、下载原始 Excel、保存草稿、启用模板（已发布时为「发布新版本」）。下载须明确对应草稿源文件或某个发布版本，避免把尚未发布的新文件当作当前可用模板。
- 基本信息：模板名称、说明、样表文件名、工作表选择。
- 主区左侧为可滚动表格，显示行列坐标、合并区域、内容、必要列宽和文本换行；网页预览不承诺还原图片、印章、复杂字体或打印版式。下载文件完整保留这些原始内容。
- 主区右侧默认只展示字段列表与「已配置 X / 共 Y 项」。点击字段进入加宽的独立编辑视图，替换整块列表；提供返回字段列表、字段设置/解析预览切换及固定底部操作，不在列表下堆叠表单和预览。字段选择与左侧表格定位、框选联动。完成配置应用到模板草稿并返回列表；取消或返回时如有未应用修改，确认放弃后恢复原字段。
- 字段表单底部展示原始内容、转换值和错误。整体验证以字段名、位置、原文、结果、提示组成的表格展示，JSON 仅作为辅助查看。
- Key 标签区使用蓝色标记，取值区使用绿色浅底与「值」标记；错误附带文字，重叠取值区可点击选择对应字段。颜色之外保留名称和状态提示。
- 对象 Key 另标记「对象标题 / 属性字段 / 属性值」三种区域。配置时在表格上方显示当前步骤；右侧列表以一个对象条目展示属性数、配置行数和已填记录数，点击对象条目后在独立编辑视图中配置属性。

## 4. 添加普通 Key 和对象 Key

用户已确认：**右键的格子作为 Key，方向表示取值方向。** 界面业务名称使用「字段（Key）」，菜单保持明确的方向文案。

例如在 A3「检验日期」右键，菜单为：

| 菜单 | 取值位置 |
| --- | --- |
| 添加为 Key（上） | A2 |
| 添加为 Key（下） | A4 |
| 添加为 Key（左） | 越过 A 列边界，不可选 |
| 添加为 Key（右） | B3；若 B3:C3 合并则为 B3:C3 |

每项同时显示实际目标地址；悬停或键盘聚焦时预览对应高亮。点击后新建字段并打开表单，不自动把它标成已配置。

同一个右键菜单额外提供独立操作「添加为对象 Key」，进入第 4.3 节的分步流程；该操作不选择上、下、左、右方向。

### 4.1 确定性区域规则

1. 点击合并单元格中的任意位置，都以整个合并块作为标签区，字段名只用该块左上角的文本预填；允许修改。空标签仍可添加，但需手填字段名。
2. 标签块为 `[r1,c1,r2,c2]` 时，相邻定位点分别为上 `(r1-1,c1)`、下 `(r2+1,c1)`、左 `(r1,c1-1)`、右 `(r1,c2+1)`。
3. 定位点位于合并区时，目标为整个合并区；否则为单格。标签跨多行或多列时，只以这个明确的定位点取一个相邻逻辑单元格，不默认扩展出同宽或同高矩形。
4. 不判断目标是否为空、是否像标题、是否像数字；不跳过空格、不寻找最近非空值、不根据内容重新定位。空白样表也可以配置。
5. 超出当前可配置网格的方向禁用并说明原因。网格按已用范围及少量空白边距展示，可显式扩展到用户输入的地址；扩展仍受行列和单元格总量上限约束。
6. 方向只帮助用户明确生成初始区域。持久化准确的 `labelRegion` 和 `valueRegion`，正式解析直接使用已保存地址，不能每次重跑方向逻辑。

### 4.2 手动修正和已有字段

字段表单允许输入地址或在表格中框选取值区域。手动修改后标记为「自定义区域」，清空当前方向，保留标签位置；点选四方向会重新明确设置取值区域。

已有标签右键显示编辑、修改取值方向、移除字段；双击只编辑已有字段，不按默认方向新增。没有字段时双击打开方向选择。Enter 或显式按钮同样打开方向选择，不暗设右方向。

普通字段支持单个添加，也支持按住 Shift 逐个点选多个逻辑单元格（合并格视为一个 Key），再次点选取消，松开 Shift 后右键已选格子保留整组，右键未选格子或普通点击则切回单选；多选时右键四方向菜单为批量添加普通 Key。统一选择取值方向后，确认框逐项展示并允许修改字段名称；默认字符串，确认时整体校验后一次添加，可随后逐个编辑。名称为空或重复时须先修正；含已有 Key 时明确报错，存在越界格时禁用对应方向；取消不写入字段。对象 Key 仍从单个标题进入向导。拖选只在用户明确进入的步骤中用于指定普通取值区域、对象属性行/列或对象值区域，不把普通矩形选区自动解释为对象。重复添加同一标签时定位已有配置；同一取值区被多个字段使用时提示共享关系，允许用户确认后保留，不静默跳过。相同顶层字段名（包括对象 Key）禁止发布。

### 4.3 对象 Key 的强制分步配置

以用户附件《采购申请单示例.xlsx》的 `Sheet1` 为设计实例，已核对实际内容：

| 用途 | 区域 | 内容 |
| --- | --- | --- |
| 对象标题 | A16:F16（合并） | 采购明细 |
| 属性字段 | A17:F17 | 名称、规格、数量、单价（元）、小计（元）、备注 |
| 属性值 | A18:F20 | 机架式服务器、存储阵列、网络交换机，共 3 条明细 |
| 合计行 | A21:F21 | 位于已选值区域外，不读取 |

操作步骤：

1. **添加对象**：在 A16 右键 →「添加为对象 Key」。按合并块记录标题区 A16:F16，名称预填「采购明细」，允许修改。进入专用框选流程，此时尚未向已配置字段列表提交对象。
2. **必须框选属性字段**：提示「请框选对象属性字段」，由用户框选 A17:F17。未选择合法属性行或属性列时不能继续；不替用户选下一行。
3. **确认属性**：框选完成后弹出确认框：「是否将以下 6 个字段添加为‘采购明细’的对象属性？」按框选方向顺序列出名称、原单元格地址及默认类型「字符串」。提供「重新框选」「确认并选择值区域」「取消添加」。空名称或重名时在确认框修正后才能确认，不能自动丢弃列或生成含糊名称。
4. **必须框选属性值区域**：确认属性后立即进入「请框选属性值区域」步骤，由用户框选 A18:F20。完成合法选区之前，不允许完成对象或切换去添加其他字段；仍可返回属性步骤或取消整个流程。
5. **预览并完成**：值区域有效后显示「6 个属性，配置 3 行，当前 3 条记录」及明细表预览。点击「完成对象配置」后一次性提交对象及其属性。所有属性初始为字符串，不依据数字外观、表头词语或单元格格式推断类型。之后可在属性配置内手动修改名称、类型、必填及数字单位等规则。

强制的是步骤与依赖，用户始终能取消。向导期间关闭编辑页、切换工作表或重新选文件，均按未完成修改处理；取消新建不留下半成品对象，取消编辑恢复原配置。对象新增完成前不能发布模板。

### 4.4 对象区域和行列映射规则

- 普通表头的属性区支持同一工作表内连续一行或一列逻辑单元格，至少一个属性；多级表头见第 4.6 节。横向按逻辑列顺序列出属性，竖向按逻辑行顺序列出属性；合并单元格作为一个属性处理，须完整选中、对齐排列。只选择一个逻辑格时可在确认框指定横向或竖向。对象标题本身可以合并，也可同时用作第一个属性。
- 值区域必须是同一工作表内连续矩形。横向属性的值区位于属性行下方，起止列与属性区相同，每行一条记录；竖向属性的值区位于属性列右侧，起止行与属性区相同，每列一条记录。例如 A3:A5 对应 B3:D5，其中 B、C、D 各为一条记录。不能自动推理、扩展值区或接纳不对齐的选区。
- 横向属性每个逻辑列对应一个属性、每个逻辑行形成一条记录，竖向属性每个逻辑行对应一个属性、每个逻辑列形成一条记录。横向示例中 A18 → 名称、B18 → 规格，依此类推；下一逻辑行形成下一条记录。值区域允许完整且对齐的合并单元格，但不得跨越不同属性或记录；不会拆分合并格、重复统计或复制相邻值补齐。
- 固定读取用户选定的 A18:F20，不扫描 A21，不自动扩展，也不判断合计行。将合计行误选进去会在预览中展示，用户需重新框选；需要更多填写行时，应在原 Excel 中预留并配置更大的明确区域。
- 读取时跳过所有配置属性均为空的记录（横向整行、竖向整列）；部分属性为空仍保留该记录，字符串空值为 `""`，再按显式必填规则报告错误。保留原 Excel 行号或列号和单元格地址供定位，不把来源信息混进业务属性名。
- 对象属性默认 `type: "string"`、`required: false`。字符串读取单元格显示文本并去首尾空白，保留千分位等显示内容；图表不会静默把它转成数字。
- 对象整体的必填表示至少有一条非全空记录；属性必填逐条校验已保留记录。只有空白预留行时，样例缺失不阻止模板发布，正式验收按必填配置处理。
- 属性可以与其他对象的属性同名，但同一对象内必须唯一；每个属性保存稳定 ID。属性类型只能选普通类型，不允许对象嵌套。
- 修改属性区域重新进入属性确认，随后强制重新核对/框选值区域。未改地址的属性保留稳定 ID 和显式配置；新增属性默认字符串，删除属性需明确提示影响，不能像 demo 一样把值区每个单元格自动生成子配置。

### 4.5 对象结构与解析示例

对象 Key 在界面称为「对象」，数据契约明确为逐行的对象数组。即使只有一条记录也返回数组，没有记录时返回 `[]`，不随记录数改变结果类型。

### 4.6 多级对象表头

对象属性步骤新增显式「表头模式」。默认普通表头继续按单行或单列逻辑格配置；选择「多级表头」后，必须选择横向（下方每行一条记录）或竖向（右侧每列一条记录），再框选包含全部层级的完整表头区域。方向、表头范围和值区域都由用户明确指定，不从内容推断。拖选到网格边缘并稍作停留后自动滚动，支持选取超出当前可视区的宽表头和值区域。

例如框选 `A1:G2`：A、B、C、G 列标题分别跨两行，`D1:F1` 为「缺点件数」，D2、E2、F2 为 CR、MA、MI。确认框生成七个平级属性，其中三个默认为「缺点件数 / CR」「缺点件数 / MA」「缺点件数 / MI」。上级标题仅用于分组路径，不单独生成数值或嵌套对象。竖向配置采用同一规则转置读取，支持三层及更多层级（最多 20 个逻辑层级）。

确认框展示完整原始路径、各级单元格区域和可编辑属性名；多语言长名称可简化，完整原文始终单独保留。所有新属性默认字符串，不依据 CR、MA、MI 等名称猜测数字类型。用户确认属性后仍须框选值区域，例如 `A3:G5`；随后在对象独立编辑器中将缺点件数属性明确设为数字，空白保持 null，零保持 0，可直接作为既有图表的数值字段。

表头必须完整包含合并格，父分组必须包含子分组，末级区域须对齐表头末端；不允许交叉分组、跨属性取值或不完整记录。相同末级名称可属于不同上级分组，最终属性显示名须唯一。上级标题覆盖整块子区域时应在 Excel 中合并对应单元格，不根据空白格自动补齐分组。

向导明确区分「仅选择表头」与「选择明细值区域」，表头选择错误附带当前步骤和选区；超过 20 层时提示检查是否误选明细，表头层数限制不作用于明细条数。值区域步骤常驻展示已确认表头地址及对应行/列要求，对象 Key 的单元格也可以作为属性表头，须由用户一并选入。选区不一致时，错误列出表头、当前值区域和需要覆盖的行/列；跨属性或跨记录的合并格错误列出具体值单元格及表头位置，提示核对备注、合计行，不自动裁剪或跳过数据。例如表头 `A9:O10` 对应明细 `A11:O31`；若属性从 B 列开始，则对应 `B11:O31`，第 32 行的 `B32:J32` 合并备注/合计不属于这组明细。

规则在对象上保存 `headerMode: "multi"` 和明确 `orientation`；每个属性保存末级 `headerCell`、原始 `headerText`、实际行/列偏移，以及 `headerPath: [{region,text}, …]`。解析时按末级区域读取平级属性，不改变图表字段 ID 的用法。重选时按原末级坐标保留属性 ID、名称和类型，并重新校验路径。普通历史对象无需迁移。保存、发布、复制、备份恢复与后续多 Sheet 验收均使用同一套规则；导入校验上级和末级原文及相关合并结构。模板和上传原始 Excel 字节保持不变。

AI 同步检查：现有 AI 没有品质模板写入工具，本次未增加工具、参数或动作卡片；多级表头仍由用户在桌面配置页面手动选择。

## 5. 字段配置与解析契约

| 配置项 | 规则 |
| --- | --- |
| 字段 ID | 系统生成，编辑名称或位置保持不变；复制模板重新生成 |
| 字段名称 | 必填，去首尾空白后模板内唯一，建议上限 60 字；默认取标签本身，不搜索周围标签 |
| 标签区域 | 由点击的逻辑单元格记录，保存当时标签文本作为版式校验依据 |
| 取值区域 | 明确的 A1 地址或矩形，可输入或选取；与当前工作表绑定 |
| 类型 | 普通字段为字符串（文本）、数字、日期、单选、多选；对象 Key 通过独立分步流程添加，包含一组默认字符串的属性 |
| 必填 | 默认关闭；缺失与格式错误分别提示，数字 0 是有效值 |
| 单位 | 数字可填，仅作含义说明；不执行单位换算 |
| 选项配置 | 单选/多选需明确勾选字符、分隔方式及允许的选项值 |
| 日期格式 | 日期类型指定允许格式，标准化为 YYYY-MM-DD |

日期类型建议本期提供，方便后续时间趋势图；它不意味着本期生成图表。

具体取值规则：

- 字符串（文本）：去首尾空白；普通字段多格按行优先顺序合并为换行文本，合并块只读一次。对象属性按对应行列单独读取，不把整个明细矩形拼成一个字符串。
- 数字：只允许一个逻辑单元格。使用 Excel 数值原值；文本数字支持明确的符号、小数和规范千分位、用户配置的单位。`12±0.2`、`10/20` 等存在多个数字的内容报格式错误，不截取第一个数字。`12%` 不能未经定义解释为 12 或 0.12，本期明确报错。不能用库存数量最多 6 位小数的规则限制质量测量值；保留原文及精度信息，超出支持精度时明确提示。
- 日期：只允许一个逻辑单元格，正确处理工作簿日期系统；文本按用户选定格式解析。模糊的日/月顺序不猜测。
- 单选/多选：可以框选一个或多个单元格。显式配置分隔方式（单元格、换行或指定字符），不按任意空白猜测选项边界。选项拆分分为两种明确模式：标记模式只按配置的勾选字符及未选中标记划分边界，不显示或使用分隔符；分隔符模式严格按指定字符拆分，不再用标记兜底，拆分后仍含多个标记则报错。勾选字符及未选中标记均支持自定义符号或文字，例如 ★/☆、[x]/[ ]；未配置符号不作为边界。分隔符保留用户明确填写的空格等字符，不以任意空白猜测选项边界。允许选项每行填写文字，也兼容带前置标记的复制文本，匹配和返回值去除前置标记。将选中标记与选项完整文字精确对应，未配置选项及去除标记后重名时报错；单选命中多个时报错，多选返回去重字符串数组。真实 Excel 复选框控件不在本期范围，仅支持单元格文字标记。
- 所有类型都保留原始内容与位置，解析错误不会被默认成 0 或成功值。选填字段非空但格式错误也报错。
- 不执行 Excel 公式，只读取缓存结果；缺少缓存或缓存为错误值时提示在 Excel 中重新计算并保存。不能保证缓存结果实时正确。
- 读取时保留实际行列索引和空行空列，不能因数组裁剪或跳过空行改变 A1 坐标。

## 6. 草稿、启用与版本

保存草稿允许普通字段未完成，结构非法的数据仍需拒绝；对象向导中的临时内容在完成前不提交为字段。启用要求模板名称有效、选定工作表、至少一个字段、所有字段规则完整、顶层字段名唯一、地址有效、区域和类型兼容；对象还需属性名唯一、属性区和值区完整且列对应合法，并在服务端重新验证。

空白样表中的必填项缺失属于样例提示，不阻止模板启用；非空样例的转换错误需提示处理。区分「配置完成」与「样表数据齐全」，避免空白模板永远无法启用。

每次启用/发布生成不可变版本，同时固定「原始文件 ID + 字段读取规则」。编辑已启用模板先保存为草稿，当前启用版本继续提供其原文件下载与规则；点击发布新版本后才切换。仅修改规则时可复用同一不可变原文件，更换 Excel 时创建新文件记录，保留旧版本文件。停用禁止新的使用和正式导入，保留历史；重新启用已有有效版本不额外创建相同版本。

并发通过 `edit_version` 乐观锁检查，冲突返回 409 并保留本地编辑内容。发布事务内再次校验草稿和版本，避免发布他人的未复核更改。

更换原始 Excel 或工作表不自动迁移字段。用户明确选择重新配置，或保留原坐标逐项复核；涉及该操作的草稿标记待核对，在用户确认全部字段之前不能发布。更换文件和修改网页字段配置是两种明确操作，字段配置本身不会修改文件内容。

## 7. 服务端、权限和备份

建议新增独立 `quality`「品质管理」业务权限，管理员默认拥有，员工需显式授权；第一阶段该权限包含模板查看、维护、Excel 下载和样例验证。后续根据实际岗位需求拆分配置、模板下载、验收录入和报表权限。前端和接口一致校验，默认不向无权限账号暴露品质数据。

### 7.1 R2 配置与文件存取

在现有「系统设置 → 备份与恢复 → Cloudflare R2 自动备份」配置区增加「Excel 目录前缀」，对应 `excel_prefix`，默认实际值为 `excel`，管理员可编辑并保存。不要求重复填写 Account ID、存储桶或密钥。

| 配置 | 用途 |
| --- | --- |
| 现有 Account ID、存储桶、Access Key ID、Secret Access Key | 数据库备份与 Excel 文件共同使用 |
| 现有 `prefix`「备份目录前缀」 | 维持现有 SQLite 备份用途 |
| 新增 `excel_prefix`「Excel 目录前缀」 | Excel 文件的独立根目录，默认 `excel` |

Excel 前缀独立于备份前缀，不拼接在备份目录下。例如备份前缀为 `77erp`，Excel 前缀为 `excel` 时，分别写入 `77erp/…sqlite` 与 `excel/…xlsx`。前缀必填、最多 200 字，去除首尾空白和斜线后不能为空，允许字母、数字、斜线、下划线和短横线，拒绝连续斜线；规范化后不能与备份前缀相同。旧配置缺少此字段时补默认值；旧客户端保存未提交此字段时保留当前值。

原文件对象键为 `{excel_prefix}/{instance_id}/templates/{file_uuid}.xlsx`，使用已有实例标识和随机文件 ID，避免同名文件或多实例之间互相覆盖。原始文件名只用于下载时的文件名展示。第二阶段填写后的文件可写入同一 Excel 前缀下的 `submissions/` 分类，具体随第二阶段设计。

上传需要 R2 连接配置完整，但不要求开启「定时备份」。服务端验证并上传新对象成功后才提交草稿引用；上传失败保留界面内容，不能显示已保存。对象写入后若数据库提交失败，应回收本次尚未被引用的对象；已被模板或历史版本引用的文件不得清理。

下载先验证模板、版本及仓库权限，再由服务端读取私有 R2 对象并以附件响应；前端不接收 R2 密钥。读取按文件记录保存的完整对象位置执行。更改 Excel 前缀仅影响后续上传，旧文件继续使用原位置；更换 R2 账户或存储桶不自动迁移旧对象，应保留旧位置记录并明确提示不可达原因，由管理员完成迁移及位置更新后恢复访问，不能直接套用新配置猜测旧文件路径。

现有备份上传函数附带「只保留最近 10 个 SQLite 备份」清理逻辑，不能直接用于 Excel。可抽取共用 R2 客户端初始化，Excel 使用独立上传/读取逻辑。数据库备份清理保持只处理其目录中符合命名规则的 SQLite 文件，Excel 文件长期保留，不参与备份轮转。

### 7.3 备份与恢复

第一阶段模板、版本、R2 文件位置与校验信息、快照和操作记录纳入业务备份、预览、恢复和重置。Excel 原文件本身保存在 R2 Excel 目录中，SQLite 完整备份与 JSON 业务备份包含数据库记录和引用，不内嵌 Excel 二进制；完整恢复需要数据库备份及其引用的 R2 原对象同时可用。备份预览明确展示模板数量、文件引用数量和外部文件依赖。

恢复保留字段 ID、原文件位置和版本关联，重新分配并发令牌；下载及发布时按权限和配置检查 R2 对象是否可读取，缺失文件明确报错并阻止操作，不能用工作表快照重建文件后冒充原始 Excel。恢复、停用及业务重置不删除 R2 原对象，避免历史版本或旧备份引用失效。导入的旧备份缺少品质数据时视为空，第一阶段备份格式升级至 v17，验收单导入阶段升级至 v18，多数据 Sheet 解析结果阶段升级至 v19（均兼容旧版）。JSON 业务备份仍不包含 R2 访问密钥，迁移环境需由管理员配置相应访问凭据。

原文件上传使用 multipart 并单独限制大小，配置 JSON 接口单独设置容量限制，避免落入当前默认 100 KB JSON 上限，也不扩大全部 API 的上限。初始建议：仅支持 .xlsx、文件不超过 10 MB、单表最多 2,000 行 / 100 列 / 50,000 个展示格、200 个字段、标准化快照不超过 5 MB；具体阈值通过真实样表验证调整。文件压缩后体积与解压后内容分别限制。只存不改原文件，解析阶段仍校验文件格式及允许范围。

## 8. 工程实现建议

- `src/pages/Quality.jsx`：品质入口及模板列表。
- `src/features/quality/`：桌面编辑器、工作表网格、字段列表、字段表单、方向菜单及对象分步框选向导。
- `src/quality/`：工作簿读取适配、坐标/合并区建模、本机草稿。
- `shared/quality-template.js`：无 DOM 的规则校验、方向定位、区域标准化、对象列映射与逐行读取、字段转换及预览；浏览器和服务端复用。
- `server/quality.js`：迁移、权限、原文件上传/下载、CRUD、发布事务和预览接口；备份及重置接入现有机制。
- `server/r2-backup.js`、`src/R2BackupSettings.jsx`：增加独立 Excel 目录前缀、旧配置兼容和校验；共用 R2 连接能力，保留数据库备份上传和轮转行为。

先用真实验收单验证读取适配。需要支持合并区、列宽、Excel 日期和公式缓存的完整工作簿读取能力；如引入库，应采用维护中的版本并按需加载，不直接复制 demo 的 `xlsx.full.min.js`（0.18.5）作为生产依赖。不改动现有物料 Excel 导入的行为。

本机读取只负责预览；原文件经服务端完整上传 R2，服务端从文件生成可信的读取模型，验证配置、发布及后续验收解析。样表数据属于模板业务资料，有权限的人员可访问，不宣称文件内容始终只留在本机。发布版本缺少有效 R2 原文件时禁止启用。

AI 同步检查必须纳入实现验收：检查 `server/ai.js`、`src/AiAssistant.jsx` 和 `tests/ai.test.js` 的权限枚举、导航及写操作边界，防止新增权限后绕过校验。第一阶段建议暂不增加 AI 创建/发布模板工具，AI 不能猜取值区域或替用户选择方向；今后增加工具时须提供明确坐标、预览和确认流程。

对象配置同样遵守用户明确选择：AI 不推断属性行、数据行、行数或属性类型。后续如提供 AI 查询与图表工具，工具 schema、列映射和动作卡片需区分顶层普通字段、对象属性和记录列表，保留对象 ID、属性 ID 及源行/列定位。

## 9. 后续解析与图表的兼容点

正式使用流程为：选择已启用模板及版本 → 下载该版本原始 Excel → 用户在 Excel 中填写配置的值区域 → 上传填写后的 Excel → 选择所用模板及版本 → 按该版本规则读取用户填写的值 → 复核后保存结果。配置用原文件与填写后文件分开保存，填写后上传不能覆盖模板原文件。

不因文件名相同就认定模板，也不默认用最新规则解析旧版本下载后填写的文件；界面需明确展示模板版本，历史版本的使用策略在第二阶段细化。第一阶段下载时已提供版本信息，确保后续能够选择对应规则。

正式验收记录至少保存 template_id、不可变模板版本、warehouse_id、填写后源文件标识、原文、按字段 ID 保存的类型化结果及逐字段错误。字段名称变化不改变身份；改变字段业务含义或不兼容类型时应新建字段。跨版本图表只合并兼容字段，不能仅按中文名称聚合。

对象属性以「对象 ID + 属性 ID」定位；图表读取对象记录列表，按行处理，避免把多条明细摊平成互不相关的单值。默认字符串不执行数值聚合，切换数值类型需发布明确规则版本。对象属性名称与表头原文分别记录，导入时按原表头位置校验结构，属性显示名称修改不要求改写原 Excel。

导入前按工作表名称、已配置标签位置与文本、相关合并结构检查版式；文字只做预先声明的空白归一化，不模糊匹配或自动纠偏。缺工作表、标签移位、取值区域结构变化时返回明确错误，人工核对后再处理，不能静默改读其他地址。

质量合格判定、上下限、抽样规则、合格率分母和图表统计口径留待后续独立设计。本期只配置取值和数据类型，不把字段解析成功解释为质量合格。

## 10. 开发顺序与验收

开发顺序：独立 Excel 前缀和 R2 原文件上传/下载及工作簿读取 → 四方向及手动取值规则 → 对象属性确认与值区域分步框选、逐行读取 → 桌面编辑与预览 → 模板持久化、权限和版本绑定 → 文件引用备份恢复和回归。

核心验收：

1. 四个方向均按标签块边界定位，合并区正确展开；相邻空白格不被跳过。
2. 整行标题、数字标签、相邻多个标签都不会触发额外推断；空标签可手动命名。
3. 手动选区可保存、重开并定位；重复字段名阻止发布，重复标签定位已有字段。
4. 数字 0、负数、小数、千分位、空值、非法多数字、公式无缓存、日期系统与选择标记得到明确结果。
5. 空白必填样表可发布；未配置字段不可发布；预览不生成正式验收记录。
6. 已启用规则不受草稿影响，新发布保留旧版本；并发保存、仓库切换和权限撤销正确处理。
7. 桌面右键菜单、显式添加按钮及键盘操作可完成四方向选择；手机端不显示新入口，现有移动 Web / PWA 导航保持可用。
8. 下载文件与上传原文件字节和 SHA-256 一致，所有工作表、格式、图片、内嵌图表、公式及打印设置均保留；字段配置不改变下载文件。
9. 替换草稿 Excel 不改变当前发布版本或历史版本的下载文件；复制模板的字段规则可独立修改，原文件保持不可变。
10. Excel 前缀默认 `excel`，可独立保存且不能与备份目录相同；关闭定时备份时仍可上传下载 Excel，备份轮转不删除 Excel。
11. 更改 Excel 前缀后旧版本仍可下载；上传失败不提交有效文件引用，下载失败有明确提示。
12. 模板、版本、R2 文件引用和快照备份恢复往返一致，旧备份兼容；缺失外部文件明确报告，业务重置不删除 R2 原对象。
13. 附件实例 A16 → A17:F17 → 属性确认 → A18:F20 完整经过强制步骤，得到 6 个字符串属性和 3 条对象记录，A21 合计不参与读取。
14. 未确认属性不能选择/提交值区，值区列不一致、空属性名、重复属性名、非法合并均阻止完成；返回和取消不残留半成品对象。
15. 默认字符串保留 `42,000.00` 等原显示内容；整行空白跳过、部分空白保留；显式数字属性转换和逐行必填错误定位正确。
16. 对象规则、稳定属性 ID、所选区域随模板版本及备份恢复完整保留；未选择的新增行不被自动扫描或纳入图表。

验证包括共享规则单元测试、API/权限与备份测试，以及桌面浏览器主流程；移动端仅检查未开放入口及现有导航无回归，不验收模板配置操作。R2 真实读写需要配置有效凭据；自动化使用隔离对象存储替身验证上传、原文件下载、文件缺失及前缀变化。原文件替换采用清空草稿字段后重新配置，已发布版本保留；属性数和行数上限仍随模板网格限制。

竖向对象规则以 `orientation: "vertical"` 和属性的 `rowOffset` 持久化；横向继续使用既有 `columnOffset`，历史模板无需迁移。解析预览保留竖向记录的源列及错误单元格地址，整列为空时跳过、部分空值保留，所有新增属性默认字符串。保存、发布、复制及备份恢复均复用同一套规则。AI 当前没有模板写入工具，本次无需扩展 AI 工具参数或动作卡片。

Shift 批量添加仅复用既有普通字段规则和保存接口，不改变数据结构、权限或 AI 工具。浏览器验证包含不连续多选、取消选中、合并取值区域、重名与已有 Key 拦截、批量取消和保存重开。

字段独立编辑复用普通及对象字段规则：取消对象属性/值区域重选会返回编辑器并保留此前未应用修改，重选完成也先返回编辑器，点击完成配置才应用到模板。列表模式不显示当前字段预览。此变更仅调整桌面交互，接口和 AI 工具保持兼容。

单选、多选的解析预览展示实际拆分结果：每段原文、提取的选项文字、匹配标记、选中/未选中/未识别状态，以及是否匹配允许选项。错误分隔符拆出的整段内容也保留展示，方便核对规则。普通字段直接展开；对象属性在各记录单元格中提供「查看拆分结果」，模板完整预览与验收结果复用同一展示。拆分与取值使用同一个共享解析函数，不在界面另写猜测逻辑；明细仅用于展示，不新增验收结果快照字段，历史结果及备份格式保持兼容。

选择类型回归覆盖同一行/换行标记、复制的带符号选项、含空格的选项名、正则特殊字符、自定义分隔符、勾选符号后的 emoji 变体、未选/多选冲突及未知选项。字段规则同时用于浏览器预览和服务端解析；不涉及 AI 参数变更。

选项规则保存 `choiceMode`（markers / separator）和 `uncheckChars`（每行一个）。旧配置未指定模式时，非默认分隔符按严格分隔符模式处理，否则使用标记模式；未选中标记默认为空，不自动填充或隐式识别 ○、◯、☐、□ 等符号；仅使用明确填写并保存的标记，已有显式配置保留，清空并保存后保持空值。标记模式隐藏分隔符，切换模式不会自动猜测符号或分隔符。浏览器与 API 共用规则，AI 当前无品质模板写入工具，无需增加参数。

合并对象区域的属性数量按逻辑单元格计数，属性偏移保存实际行/列偏移；解析结果保留完整合并区域与记录起始行/列。错误直接显示在框选步骤下方。现有未合并对象无需迁移，Excel 原文件始终保持原样。

所有标量类型（字符串、唯一 KEY、数字、日期、单选、多选）及对象内的每个属性均支持「解析行」和「忽略内容」。解析行默认所有行，也可按当前取值内容选择单元格内部的第 N 行文字；对象属性的候选项根据样表记录最大文字行数生成，已有选中行号始终保留。行号包含空白行，兼容 LF、CRLF、CR；不代表 Excel 的记录行号，也不改变框选的对象值区域。导入的非空单元格缺少所选文字行时，按原位置报告错误，不回退到其他行。

处理顺序为取指定文字行 → 按顺序删除忽略内容 → 去除首尾空白 → 原有类型解析及必填校验。忽略内容每行一条，保留规则中的空格，忽略空规则，逐条按字面删除所有相同内容，区分大小写，无正则或自动匹配。过滤后为空仍执行必填校验，数值 0 继续保留；改变显示文本后不得使用 Excel 缓存数字或日期绕过规则。未启用设置的历史字段与解析快照形状保持兼容。

普通字段的预览显示原始内容、处理后内容、选项拆分（选择类型）和最终值；对象记录中通过「查看内容处理」核对各属性的原文与处理结果。两处复用共享预处理函数，与服务端验收解析一致；源表头匹配不受影响，原 Excel 不变。规则随草稿、发布版本、复制及备份恢复保存，同一份模板用于多个 Sheet 时逐格处理。本次检查 AI 工具：当前无品质模板写入工具，无需更新 AI schema 或动作卡片。

## 出货报告稳定导入

新增可选的 `markerPosition: "after"` 支持同一行文字后勾选（如「合格■ 拒收□」），缺省保留原有解析逻辑。新增 `specialValues: [{text,status}]`，在文字预处理后完整匹配为 `not_applicable` 或 `missing`；解析快照保留原文与状态，值为 null。不适用可通过必填检查，未填写仍受必填约束；唯一 KEY 禁用该映射。

对象字符串属性支持 `itemRules: [{matchPropertyId,equals,config}]`，精确匹配同对象中未经项目规则覆盖的字符串/唯一 KEY 属性的预处理文字。命中后使用独立类型与规则读取目标逻辑单元格；未命中使用默认字符串规则。规则不可嵌套或定义唯一 KEY，解析结果保留命中的 `ruleIndex`，复制模板同步重建属性引用。混合类型属性暂不作为图表候选字段。

桌面模板编辑器提供 JSON 字段配置导入，读取并验证后仅替换当前草稿，仍需人工预览、保存与发布。对应真实报告的配置与操作说明见 [航嘉出货报告导入配置](examples/hangjia-shipping-template.md)。本阶段不拆分测量列表，不推断不适用，不自动执行公差/AQL 判定。

## 自动核对与测量值

新增 `measurements` 类型，按明确配置的 `separator` 拆成数字数组，先执行取行、忽略内容和特殊值映射。空项、非数字及超出数值/数量限制报解析错误。旧字符串类型不会自动改为测量数组。

模板可选 `checks` 配置包括 `range`（样本共用限值或部位逐个限值，支持严格/包含边界及检验要求文字绑定）、`sum`（明细缺陷数与合计/头部不良数核对）、`acceptance`（读取报告 Ac/Re，不推导抽样标准）、`decision`（单项结果、单项判定、已配置公差/允收与最终判定的一致性）。所有引用采用字段和属性 ID，可指定项目精确匹配；复制时同步重建引用。多 Sheet 分别执行，不跨 Sheet 合并。

解析快照按 Sheet 保存独立 `checks` 结果，包括状态、来源位置、实测值和限值；原报告判定不被覆盖。状态区分 `pass`、`fail`、`review` 和 `not_applicable`。规则为空的历史模板不增加快照字段。结构错误、解析错误、缺失结果、要求改变不能得出自动通过结论。

桌面模板编辑器提供核对配置，预览与验收详情展示结果；导入时可以定位源单元格。差异或待人工核对项要求勾选确认，服务端同样强制校验；验收单 `checks_acknowledged` 与提交人和保存时间记录此次确认。业务备份升级为 22，旧备份默认确认状态为 0，新备份校验重算结果与确认状态。具体报告配置见 [航嘉出货报告自动核对](examples/hangjia-shipping-checks.md)。


### 字符串与数字的正则替换

普通字段、对象属性及按项目规则中的字符串和数字类型可配置 `regexPattern`（最多 1000 字符）和 `regexReplacement`（最多 2000 字符）。两项都为空时不启用；只填替换内容会提示补全表达式。表达式与替换文本保留配置中的空格。

执行顺序为取解析行 → 删除字面忽略内容 → 正则全局替换 → 特殊值映射 → 类型转换和必填校验。替换为空表示删除，支持 `$1`、`$2`、`$&`、`$$` 等 JavaScript 替换引用；表达式直接填写，不使用 `/…/g` 包裹，可通过 `(?i)` 忽略大小写。使用前后端共享的 RE2JS 引擎，支持常见字符类、分组和量词，不支持前后查找及表达式内的反向引用。正则处理原文及处理后文本各不超过 10000 字符。

模板编辑预览、浏览器 Worker 验收预览、服务端保存重算使用相同规则。原始 Excel 和预览原文不改写；数字使用替换后的内容做严格转换，空值不自动变为零。切换到不支持正则替换的类型时清除正则配置。规则随模板草稿、发布版本、复制及备份保存。
